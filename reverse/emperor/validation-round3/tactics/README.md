# 战场招降、停战与主将：第三轮静态恢复

本目录结论为 EMPEROR 静态指令证据；尚无 DOS 动态验证。地址采用重定位 VA；读档结构不可套用 KING 的同数地址。T 为向零整数除法。`battle_dispatch.asm` 有内嵌跳转表，线性解码该部分出现伪指令；本轮直接读取原始 dword 跳转表核实七选项映射。

## 主将与兵种

0x84e14..84f53 通过官员链表 ID=battle+0x6fc 取得主将。中国主将 slot0 为 type3、N100。battle+0x391=官员+0xc（智慧）+0xe（武力）+0x12（忠诚），因此攻击公式的阵营项是三属性之和，不是独立的统帅技能。主将训练 byte=T(武力²/80) 的低八位；主将防御 word=T((智慧+忠诚)*10/15)。官员+0x10（清廉）不进入这三条公式。

外国主将 battle+0x393=地区 c9ae2+c9ae4+c9ae6，slot0为type3。其属性中文名仍待字段UI链核实。

运行时消息0x124说明兵种“步兵克槍兵，槍兵克騎兵，騎兵克步兵”，结合初始化库存链，数字type0应称步兵（装备刀），type1枪兵，type2骑兵。原始相克表依然不对称，不能按这段说明替换实际数字。

## 招降及停战基于加权军力

0x85a60 遍历每侧全部45槽，type!=FF 的槽（含主将）累加：

`P = sum(T(N*(50+训练u8+防御i16)/50))`

累加为word，A侧写battle+0x702，B侧写+0x700。谈判读取无符号word后 `R=T(100*P_A/P_B)`，P_B=0设R1000。不是裸兵数或攻击值之比。

0x5f611..5f91d 的我方招降选择：

|选择|业务|成功条件/概率|效果|
|---|---|---|---|
|0|敌方割地投降|R<75时 random%100<T((75-R)/2)|结束标记winner2，outcome2，播放msg12f；归属由战后分支办理|
|1|敌国成为我国藩属|R<100时 random%100<100-R|该国关系对象+1e=3；全局状态4；winner2/outcome3；msg130；记事件0x13|
|2|敌方赔款投降|必成功|金额=10*地区 dword c9a38；皇帝资金+45和收入+4d增加金额；winner2/outcome3；msg131|

注意R越低越容易招降，说明A/B数组与“我/敌”标签不能按数组名推断；中国初始化在B侧。

0x5e686..5e931 是敌方要求我投降的自动条件选择：仅battle+12非0处理；R>100时先以 T((R-100)/4) 抽割地（0），未中再独立同阈值抽藩属（1），两者都不中选择赔款（2）。该概率函数没有钳制，R>=500必选割地。玩家确认后0x5fa28..5fb92分别设置winner1和结果；藩属关系对象+1e=4，全局状态3，国家计数字段皇帝+2c0减1；赔款从资金扣除并计入支出+71。

## 七种停战选项

入口0x5fd48..60503。选项序号来自参数word+1c。直接读取object1在0x5ff9c的跳转表，确认中国攻防方向下的七选项分支映射。方向字段battle+12非0与为0时条件不同。

|选择|业务|方向非0|方向0|
|---|---|---|---|
|0|无条件休兵|R<100必成功|R<100必成功|
|1|互不侵犯|必失败|R<75必成功|
|2|防御同盟|必失败|R<90必成功|
|3|敌国成为我藩属|必失败|R<75时阈值2*(75-R)|
|4|敌方赔款|必失败|R<90时阈值2*(100-R)|
|5|我方贡金|R<=110必成功；110<R<200阈值220-R；R>=200阈值20|必成功|
|6|我国成为敌藩属|同选项5|必成功|

成功时先将关系对象+1e和全局国别状态均清0，然后按选项覆盖：互不侵犯→1/1；防御同盟→2/2；敌藩属→3/4；我藩属→4/3并皇帝+2c0减1。停战赔款金额为2*地区dword c9a38（不同于招降的10倍），增加资金/收入。我国贡金固定50000，减少资金/增加支出。具体状态UI和副作用在0x60047..60312。显示消息134/136/138/13a/13c/13e/140。

## 装备随伤亡损耗

0x5a11b 对中国非slot0计算百分比 q=T(loss*100/N_before)，逐项头盔/皮甲/皮盾 E'=max(0,E-T(E*q/100))，然后战斗累计阵亡+6f8增加loss，最后N减loss。此处是两次整数截断，不能改成 E'=T(E*(N-loss)/N)。slot0只扣N，不进普通阵亡与装备损耗分支。外方队消灭0x59f83把尚存N加+6fa，type置FF、棋盘位置清FF、N0。

## 消息表重要修正

2ef01真实使用cd3e8运行时消息表。0x34130初始化时从c71xx原表逐项重排，原表c71ec+id*4不能直接用于调用编号。`runtime-messages.json`按实际初始化指令恢复所有消息。战场消息125部署不足，127撤退确认，128撤退遭追杀，129..132投降，133..141停战，142..143援军，144..148回合统计。

## 可直接 DOS 差分的预测

1. 官员I80/M40/L60：阵营项180、主将训练20、防御93；改清廉不变攻防，改忠诚+15：阵营项+15、防御+10。
2. 一队N100训练30防御100：加权军力360；N100训练0防御0：100。45槽都空时P0；slot0有兵依然纳入统计。
3. 非slot0 N100/E99/loss1：q1，E99（装备零损耗）；loss2：q2，E98。N99/E99/loss1：q1，E99。这与理想比例结果不同。
4. 招降选项2任何R必走成功分支，地区c9a38=1234赔款12340；停战选项4成功赔款2468。
5. 停战方向0，R74选项1必成功、R75必失败；R89选项2必成功、R90必失败。方向非0，选项1和2恒失败。
6. 停战方向非0选项5或6，R110必成功；R111阈值109也必成功（概率函数不钳制）；R199阈值21；R200阈值20。

## 未完成与负证据边界

尚未确认unit+17特殊标记中文名，战场远程/计谋动作是否独立功能。限定扫描0x56000..0x69000中概率函数调用，命中只在投降与停战分支；不能据此断言无计谋。撤退确认与UI结果已定位，追杀数值在战后回收处理中，不能把msg128视为精确损失公式。DOS动态覆盖需主线记录，不能把以上静态预测当作实机通过。
