# DOS 原函数动态验证

使用官方 [DOSBox-X 2026.10.01 ARM64发行包](https://github.com/joncampbell123/dosbox-x/releases/tag/dosbox-x-v2026.10.01)，SHA256 `8514ab856e8ac2611fbdac7adf334c34085c1e00d700a88711f842adec50240f`。配置及本地调试桥见 test.conf、bridge.py；协议依据发行版 README.debugger。游戏副本启动原始 EMPEROR.EXE 与 DOS4GW。captures/emperor_000.png 是原游戏画面。

## 方法和可复现证据

先在真实游戏32位代码上下文断下：CS160，DS/SS168。代码对象实际基址1E0000，数据对象276000；两者重定位增量不同。probe.py 将原函数参数和返回断点写入有效原栈，执行原始x86指令直至返回。分配、文件读写、随机及其他被调函数均由原程序/DOS执行，没有逻辑桩。load91C87在每组实验前读取原KING1；PRNG种子固定12345。save91D91将输出写入副本KING4再复制checks。静态VA均为EMPEROR。

此方法是模拟DOS系统内的原函数受控执行，并非物理DOS主机或完整菜单端到端操作。最初曾从DOS内核中断上下文强制切段调用，未正确返回；该失败不计通过。改为真实游戏段上下文后完成以下实验。早期战后夹具曾误设单位宽度，结果失败；改为兵数word+4、训练byte+12、装备word+6/+8/+10后才得到通过记录。

## 公式核实范围

兵员80%在合计后截断；装备逐队截断的代码已恢复，上述单队实测验证了80%回收和训练加权。多队尾数差异已由 rounding-live.json 独立实测。训练使用最后匹配队的训练+10与留守兵加权；本次单队不能单独证明“最后队”选择规则，此项仍由静态证据支持。总回合更新调用已执行，未声称每个灾害/事件分支均动态通过。招降及七选项停战概率表是静态完整分支恢复，当前动态军力验证不等同七选项全部实测。

probe.py、live_checks.py、calendar_live.py、war_live.py、power_live.py、aux_live.py用于有相同原程序段映射的当前DOS调试会话；不是可直接用于任意启动地址的通用工具。数据/代码基址、原栈限制和对象指针须重新确认。
