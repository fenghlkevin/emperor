# 战后结算第三轮恢复

本目录结论是 EMPEROR 静态指令证据，尚不属于 DOS 实机验收。地址以 object1 VA 为准。`evidence.py` 重生成7份完整片段并从原始 relocated binary 读取两张跳转表，解决线性反汇编将跳转表误解为指令的问题。地区字段以第一条字段基准 0xc99ae 为准，地区运行对象基址另减2。B是中国/玩家及其属地一侧；A是来敌/目标国及其援军。

## 结果代码和完整调用链

窗口对象 W+0x5d 指向战斗 BATTLE。W+0x80=1 表示 A 胜/B败；=2 表示 B胜/A败；=0 表示尚未结束。W+0x81 是结束原因：0 主将消灭、1 撤退、2 投降并交出领土、3 条件投降（称臣或金钱）、4 双方常规队全部消失而主将槽仍存在。80/81是窗口状态，并不等于战斗存档记录同偏移。

主将判胜在 0x5edb3 检测B槽0 type==0xff→1/0；0x5ee00检测A槽0→2/0。0x66607只扫描两边 slot1..44 的 type，全部0xff触发2/4。不能将这个分支理解为双方主将也消灭。

0x6564e 是战斗一阶段结束/下一战推进：增加 BATTLE+0x1a；销毁UI→0x6441b→若结果非0则0x6668f→从0xcc5e0链表摘下当前0xcc5e8（包含战斗record和链表节点分别free）→如还有下一record则0x65cca。若最后属地丢失产生 W+0x11a=1，则皇帝+0x19=0、+0xf=0x80、+0x10=0，走游戏结束状态，不摘当前record的正常分支。

0x6668f初段执行：

|结束状态|先执行的兵员/人口函数|
|---|---|
|80=1,81=0|仅0x67e9d外援损失；不归还B兵装|
|80=2,81=0|0x6775f归还B兵装→0x67d9e A主国人口损失|
|81!=0|0x67e9d外援损失→0x6775f归还B兵装→0x67d9e A主国人口损失|

随后根据 BATTLE+0x6fc/+0x6fe 查官员链表0xc992c。原因1/3/4，非属地战将领职位byte+2置0，属地战两个将领职位恢复为地区0xc99b0低byte。战后清除战争状态5为0，不自动恢复贸易额度。

## B侧兵装回库、训练与人口

0x6775f只扫描B slot1..44，跳过type=0xff，仅处理 country=30（中央军）或 country=BATTLE+0x390（本地驻军）；其他援军不归入这两库。分别统计生还总数。中央军训练取最后一个匹配队的训练byte，本地驻军也如此，**并非按每队训练平均**。

当80=1且81=1时，回收系数Q=80，否则Q=100。先对两类**总兵数**作 T(total*Q/100)；装备和武器则对**每一队**分别取整后加总，因此会有尾数差异。

```text
central_training = min(100,T((oldN*oldTraining+returnedN*min(100,lastTraining+10))/(oldN+returnedN)))
central_soldiers += returnedN
local_training 同式，local_soldiers += returnedN（仅BATTLE+0x12非0即属地战）
local_population -= initial_local_3types_total - returned_local_total
helmet/armor/shield += T(unit_equipment*Q/100)
knife/spear/horse[type] += T(unit_survivors*Q/100)
```

分母为0则训练置0；无最低0钳制。中央地址士兵0xcc14c、训练0xcc1b2；地方士兵0xc99ce、训练0xc9a34；人口0xc9a38。中央军装备也通过 country=30 的第31条特殊地区对象回库，不能错误加到战场属地库存。生还训练+10再与留守兵加权；并非整个地区训练直接+10。

A主国人口0x67d9e：统计A侧 country=BATTLE+0x5d 生还兵员，80=2且81=1时生还总数乘80%；人口减 `BATTLE[0x5f]+[0x61]+[0x63]-adjusted_survivors`。A侧兵装没有对称回库函数，敌国士兵通常为动员派生，而中国兵装出战时实际扣库。

外援人口0x67e9d：按国别累积 `100-unit_survivors`。非属地战统计A侧除A主国；属地战统计B侧除本地和30。注意它检查A的country byte+0x67是否0xff，而不是type；随后属地分支才读取B。每队初始不足100者仍按100减，这一可疑行为应优先动态测定，不能擅自改成初始队人数。

## 领土、关系、经济、官职

原始跳转表0x67280证实B胜时原因0/2都进入0x668bf吞并；1/3/4进入0x6725e只调用地区更新0x3ba99。吞并将皇帝+0x2e属地数加1、目标地区统治0xc99ae=1、职级0xc99b0=1、byte0xc9a6b=1。并按人口与byte0xc9aea..0xc9aed的百分比重建四类从业人口，0xc9aee重建士兵；四类人口总和写0xc99d0。0xc9afb±随机5作为生产基率，重新计算产出及率；清除目标国与30国双向关系矩阵，重建地方官职及地图状态。故新占领国不是保留原先外国的全部生产缓存。

原始跳转表0x67718证实B败时原因0/2都进入0x672e4；1/3/4不丢领土。非属地战只撤掉将领节点。属地战：皇帝属地数减1；被攻占属地与侵略国关系分别置4/3，侵略国对中国状态6；属地统治和职位清0，0xc9a6b清0，按人口*动员率重建外国士兵，删除两个将领节点，友好度向零除2。20条15字节地区建设/相关投资记录中相同地区项改100，同时皇帝+0x96扣该条dword金额；并清空若干内政工程/贸易辅助状态，0xc9ad5浮点恢复1.0。具体byte的UI名称不由此孤立赋值猜测。

条件投降分支0x5f79c /0x5fa5e分别写称臣/保护关系，原因统一3但方向不同；金钱分支0x5f828胜方加 `人口*10` 到资金+0x45与收入+0x4d，败方0x5faf7将协商金额W+0x7c从资金扣除并加入支出+0x71。称臣败方另将皇帝word+0x2c0减1。因此不能把81=3统一当作赔款。UI具体选项与计谋任务报告结合核对。

## 可测试预测与边界

见 `scenarios.json`；这些是静态模型预期，不是实测结果。优先对比战前、临结束、结束后同槽存档，校验other_records删除与地区库存变化；存档加载本身会调用更新，必须保留“保存后未经再加载”输出作为真实差分。

剩余：异常修改器负数/word溢出、中央军训练无匹配队时局部栈值、援军未满100队的损失基数、最后属地失败后残留record，均需要实机或原函数运行证据。正常正值公式已逐条确认；未将静态模型验证写成DOS动态验证。

## 动态验证补充

本轮随后在DOSBox-X内执行原函数6775F、67E9D：正常归队、撤退归队、两队1+4的尾数差异、援军15生还扣85人口全部通过。见 [DOS报告](../runtime/README.md) 及 war-live/rounding-live/aux-live.json。其他领土、删除链表和最后属地分支仍仅静态恢复，勿将本补充扩展为全部分支通过。
