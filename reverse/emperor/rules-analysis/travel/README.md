## 庆贺事件（并非必然）

事件扫描 7FFA8..80006：目的地贫富等级 R+5E >=1、目的地不为FF、E+28 >=200，才将事件21入队；没有随机数判断。消息构造 5C408..5C479 显示 D8“舞狮庆贺、饮酒作乐”。完成事件 5E077..5E0AB：目标地区 R+94 的 s16 民忠额外修正 +=2，清目的地为FF。不是直接提高贫富或国库收入，也不是每旬额外+2。

边界注意：原版先按目的地算地址读贫富，再判目的地FF；项目应采用安全的先校验索引，不复制潜在越界行为。

## 皇威与威望不能混用

庆贺门槛读的是 E+28 综合皇威分。39A32..39B47 清零重算它：受治地区按贫富0..4查原表 C8BCC `[8,14,20,28,40]` 加分；附属地方贡献20；再加 E+2F/100、E+2C0、16特殊设施模板分。没有100或1000上限。

真正威望 E+2B8 经3975B封100，与 E+28 是不同字段。因此不能将庆贺200简单换成项目 `prestige>=20`，也不能声称出巡固定加皇威。攻略“耀显皇威”是文案/玩法概括，未在此分支见到直接皇威增量。

项目若只有0..100生活水平，可明示将其量化为五档；原版贫富>=1适配为生活水平>=25只是项目选择。项目没有完整民忠重算模型时可把额外修正+2适配为即时民忠+2并保留出巡记录；不能每旬累加奖励。

## 验证边界

`verify_travel.py` 执行原反汇编快乐/寿命helper，共6用例（快乐70/100封顶、寿命饱和及快速模式10不放大），另对5条关键写入指令和体力原表做断言；导出8份可定位asm和 JSON。它不执行绘图/动画/UI，不能称为完整 DOS 巡游实测。
