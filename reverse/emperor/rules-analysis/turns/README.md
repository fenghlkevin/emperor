# 时间调度、月支出与年度变化

地址为KING.EXE静态LE地址；数据和函数均来自`object1.relocated.asm`。`verify_calendar.py`与`verify_expenses.py`使用有限指令解释器执行这些已反汇编指令，外部业务调用明确记录或stub。它们不是DOS运行、游戏UI验收或完整回合模拟。原始代码片段及JSON验证结果在本目录。

## 精确时间层级与顺序

全局0xC9840为年序号，0xC9841为月序号0..11，0xC9842为旬阶段0..1，0xC9843为阶段内行动进度。指针表0xC5054/58对应Big5“上旬”“下旬”，没有第三个中旬。按程序定义一月两阶段，一年24阶段，不能擅按现实三旬模型复刻。

普通行动入口0x11F65：

1. 先调用0x13577，月份0/6且阶段0时，将皇帝主结构E+0x4D..0x71的10个收入/支出分类dword归零。
2. 清本次事件数量0xCC9AE及10个word事件列表0xCC99A。
3. 根据当前场景ID，行动进度加原始表`0xC3898[scene]`。scene13/14直接将进度置3；快速标志0xCCC85==1且scene12另外加3。
4. 若进度>=3，只推进**一次**阶段并将进度归0（超出量丢弃）。清E+0x2C2/2C3两个本阶段标记，阶段+1；依次执行计时矩阵0x13630、地区/工程/训练推进0x13825。
5. 阶段>=2时阶段归0、月+1，然后执行月更新0x120C7。
6. 月>=12时月归0、年+1，然后执行年更新0x133C8。
7. 更新后月份为0或6时执行半年结算0x123E6。

因此十二月末进入新年时，顺序是：先旧年份最后一阶段的地区推进 → 月更新/工资 → 年更新/年龄 → 新年半年税收/人口/贸易结算。不得把半年税收提前到工资之前。

0x13485为强制推进到下一月边界：若当前上旬会执行两次阶段业务，若当前下旬只执行一次；随后月/年/半年顺序相同，最后行动进度归0。0x101EC的场景3（特定状态）及场景15/18成功分支调用它；现有证据不能把它误称为“每次读档都调用”。是否读档后其它函数推进，应从实际load入口另追。

分类账归零条件检查在**每次**行动之前，条件没有限制行动进度=0，所以处于一月/七月上旬的多次行动可反复清分类统计。这不清资金存量E+45。准确作者意图不可从机器码判断。

验证：11个指令解释用例覆盖正常累积、阶段/月/半年/年边界、特殊场景、快速标志、两阶段强制月推进、超额进度丢弃；`calendar-verification.json`保留实际调用次序与清零结果。

## 月更新0x120C7

- 0xCC9B6非0时执行针对官员状态的效果、计数减1，减到0时清3个关联计时字节。精确任务名未确定。
- 遍历34后宫槽（步长19）：怀孕计数非0就+1。它是月龄计数而非简单bool。
- 遍历30地区，仅受统治且R+4==3时自动选当前四行业效率最低的一项为开发方向；平局保留较早行业。开发辅助0x3AFC7执行后由官员效果辅助0x8A9AA增加民忠，上限100。
- 调用0x13109执行月维护/人口支出/官员/爵位/军队/民夫工资。
- 17项行动/官员调用标记：索引1/2/15/16按当前月份匹配清除；3..14按`month/3`季度匹配清除。数组0xC9828与0xC9814尚未把每个索引名字完全对应，但期限行为明确。

## 月支出0x13109

完整地区R=0xC990C+i*337；E为0xC9810指向的皇帝状态。D表示有符号除法向零截断。

```
P = sum(受统治地区 R+0x24)
N = sum(受统治地区 R+0x22) + 中央士兵0xCC0AC
建筑维护 = sum(各地区7类建筑等级 * 对应模板月维护)
          + sum(16特殊设施中 E+0x298+i*2==1 的模板月维护)
人口项 = D(P,2)
官员项 = 40*在职官员数 + 20*散官数
爵位项 = sum(每名官员的爵位工资)
民夫项 = 4 * E+0x96
军队项 = 4 * N
资金E+0x45 -= 以上六项之和
```

六类统计分别累加至E+0x6D（建筑）、+0x51（人口）、+0x55（官员）、+0x61（爵位）、+0x5D（民夫）、+0x59（军队）。没有余额不足保护，因此资金可变负。人口项用途为固定人口比例支出，最终中文账目名尚未通过字符串表核验，不直接断言它是用户主动补助。

官员运行时+1职位值0x4D是散官；每名官员先收职位工资，再收爵位工资。爵位0..6对应王、公、侯、伯、子、男、无，工资为[600,300,160,80,30,10,0]。原始表0xC8AE2。

普通模板顺序0市集、1义仓、2寺庙、3衙门、4城墙、5校场、6行宫。前六类月维护均10，行宫200。23项原始建筑模板是22字节记录，表0xC505C；名称、3个dword和3个word无损导出`building-templates.json/csv`，月维护来自记录+12。特殊设施维护200..500，详见表。特殊设施状态**只在==1时**被这个工资分支计入，不能以“非0”为条件替换。

指令验证合成状态：一受统治地区P=1501、兵126，中央兵13，民夫11，一在职王爵、一散官男爵，普通等级[1,2,2,2,1,1,0]及第一特殊设施状态1。解释所得六项[290,750,60,610,44,556]、合计2310，资金100000→97690；非受统治地区大量人口/兵和状态2特殊设施被正确忽略。`expense-verification.json`保留证据。

## 年更新0x133C8

- E+0x0E年龄byte加1。
- 34个后宫槽年龄byte（槽+9）均加1，代码未先检查占用，因此空槽残留年龄也推进。
- 官员链表每个年龄byte（+11）加1，函数0x2E92E。
- 子女链表每个年龄byte（+8）加1，函数0x7E8B9；对应存档子女+7。
- 非受统治且贸易额度非0地区的贸易年数word加1。

年龄计数无饱和保护，写入byte会低8位回绕。寿命/健康/怀孕出生及死亡检查属于另一路事件/个人状态逻辑，详见生命周期报告，不能等同这个年龄+1函数。
