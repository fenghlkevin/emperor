本轮沿用已提取的程序与存档，补充反汇编调用链、业务字段、整数规则与可重复验证。输入程序及存档未修改。完整原文件/哈希见上级目录；本轮主体使用KING内政/时间/生命周期，以及EMPEROR外交/战争，各报告明确版本与地址，不能把二者PC混用。

## 最重要的结论

1. **存档最后33字节已核实**：游戏保存例程无条件再次写出后宫肖像已用数组的前13字节和完整20字节。正式20字节数组此前已保存并被读入，两个尾副本不被加载器读取。KING、EMPEROR、QUICK均如此，KING1/2/3逐字节吻合。不是额外属性或校验和。作者追加它们的理由尚不能证明。
2. 时间分为行动、上/下旬两阶段、月、年及半年。每月两阶段，一年24阶段。地区/工程/灾害/训练在阶段变化时更新；工资在月变化时扣；年龄与贸易年数在年变化时增加；税收、人口增长、贸易利润和保护费在半年边界结算。
3. 修改器称作“现金”的地区字段实际参与财富积分及贫富升降，允许负值。升级阈值[60,65,70,80]，单次只升一级；降级阈值[-40,-50,-60,-70]。
4. 人口增长存在已按字面指令核对的共享变量行为：低积粮地区沿用税收循环最后地区的财富变化；一旦前一地区积粮>=100，后续低积粮地区沿用100。不能用理想化“本地积粮决定增长”替代原程序。
5. 贸易初始利润率-20，正常前期可亏损；每次半年结算按友好度/20增加，最高50。贸易/勒索正常接受门槛为友好度>=41。四种条约分别有不同成功阈值，和亲、进贡、勒索的确认路径不能一概当随机概率。
6. 战斗双方各45个18字节部队槽，兵员、装备、训练、攻击、防御、兵种及特殊标记已恢复。保存/读取代码直接复制两个810字节数组，所以也会出现在1793字节战斗存档块里。三份自带存档没有活动战斗记录，已用合成记录验证解析边界。
7. 读档恢复路径会额外运行一次地区更新0x13825；这段本身没有直接月份+1。攻略“每次读档一定前进一月”不能作为已验证规则。额外地区更新可能推进工程、训练或事件，具体UI表现仍待DOS差分验证。

## 地址和宽度纠正

完整地区对象R包含2字节前缀：KING R0=0xC990C、EMPEROR R0=0xC99AC，步长337。磁盘第0字段被复制到R+2（KING C990E、EMPEROR C99AE）。第一轮某候选地址C998E有误，已修正join脚本与表。内政报告用R偏移；战争主报告用R+2数据起点，其外交补充改用R，阅读时必须按表头，不直接混用。

新增加载证据：贸易收入磁盘记录+184是signed16，0x92F42 `movsx`扩为运行时32位并于0x92F53写R+0xB2。旧只匹配`mov`的提取器漏掉该字段，现在支持movsx/movzx、分别记录磁盘/运行时宽度。修改器声明2字节只能说明控件行为，不能作为运行时struct类型。已关联字段由43增至44，原三存档地区值由3999增至4092。

皇帝年龄是存档绝对24处的u8，25是独立状态；旧u16候选被纠正。子女存档+7年龄、+8性别；后宫+15怀孕月计数、+16老年死亡概率累积、+17肖像。这些都保留原始字节和旧候选名称以便追溯。
