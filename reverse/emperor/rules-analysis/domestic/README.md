## 地址与整数约定

完整地区指针 `R=0xC990C+i*337`，存档布局既有 `runtime_relative_offset` 以统治标记为0，即比本报告R偏移少2。地区加载证实KING统治标记基址C990E，EMPEROR C99AE。旧join文件C998E候选已纠正，磁盘映射未变。

`D(x,n)` 表示x86有符号除法向零截断；无符号div特别注明。先后截断不可合并为单个浮点式。word/byte写回保留低16/8位；大量word再次用movsx读取，因此磁盘u16中32768以上值会参与负数计算。下列公式正常数值下成立；字段被修改器改到极端值时须按溢出和符号扩展执行。

## 半年结算：0x123E6，月份0/6调用

仅处理玩家统治的30地区（不包含第31中央槽）。先把四行业剩余百分比各减去R+128（byte减法，无下限保护）。令n=(农/牧/商/工人数)，e=(R+54/56/58/5A)，m=(R+11F/121/120/122)。

```
a = D(e农*n农,100) * m农
b = D(e牧*n牧,100) * m牧
c = unsigned_div((D(e商*n商,100)*m商)*(体能+50),100)
d = D(e工*n工,100) * m工
q = (R+24 != 0) ? unsigned_div(a+b+c+d,R+24) : 0
q = s16(q)
q = min(q, 2*民忠)
```

证据12557..126C7，商人额外乘 **体能+50** 是字段对应代码的结果；不要因“营业”名称而擅自改成营业。随后四m重置100，R+128清零（126E3..12731）。

税率为全局字节0xC8AFF（在代码读取处明确，不等同地区字段）。财富变化（12786..12810）：

```
wealth += q - D(q*tax,100) - (贫富等级*15+60)
if wealth < -100: wealth = -99
wealth_level_step(R)   # 0x3B31D，单次最多升降一级
税额 = D( D(R+24,100) * q * tax * (R+A4),100 )
全局主结构+49 += 税额
```

+49本次先清零，循环后加到主结构+45（128A9..128B7）。因此+49是本次税收统计，+45是资金存量候选；税额用的q仍是升降贫富前人均收益。

人口增长（128EF..12A44）：

```
# 机器码特殊行为：若积粮>=100，local_f0=100；若<100，没有把积粮写进local_f0
# local_f0跨地区持久化：初值为前一个税收for循环最后处理地区的wealth_delta。
# 某个人口地区积粮>=100会将local_f0改100，此后积粮<100地区继续沿用100。
if 积粮>=100: local_f0=100
x = local_f0
r = D((民忠 + D(s16(x),2))*15,10)
各职业人数 += D(D(各职业人数,100)*s16(r),100)
```

这是静态直接可见的疑似原程序bug：128F9仅加载积粮到eax，12900比较，12905仅在>=100时写[ebp-10]；其余路径沿用127D9税收循环最后一个受统治地区写入的财富变化，或人口循环前面某地区已写入的100。税收循环与人口循环是两个独立for，不能按本地区财富变化解释。不能把理想公式替代实际指令。总人口字段未在这段立即重算；其他函数会重新聚合。

## 贫富升降级：0x3B31D

`constants.json`恢复原始阈值：升级[60,65,70,80,100]，降级[-99,-40,-50,-60,-70]。

```
if wealth>=0:
  if level<4 and wealth>=UP[level]: wealth-=UP[level]; level++
else:
  if level!=0 and wealth<=DOWN[level]: wealth-=DOWN[level]; level--
```

一次调用仅一级，无while。等级0负债不再降级；等级4正财富不继续升级。写回16位。

## 每半月地区推进：0x13825

资金+45<0且月份不是5/11时调用0x1371E：主结构+2BE减1，所有受统治地区wealth减3、钳到-99，随后调用贫富升降级；额外收入`Σ(R+24*3)`计入主结构+8E/+4D/+45（1371E..13824）。这与“资金不足时加税/苛捐”行为一致，精确菜单名待字符串核对。

常规推进先对玩家地区处理工程/灾害/训练/增援/赈济，非玩家仅重算0x3BA79军事负担后跳过。

- R+134非零时加1（138DF..138F4），具体业务名仍未知。
- R+D3==1：取D(R+24,1000)调用0x3B3DD分摊扣除职业人口，另取D(2*(R+24),1000)增加R+1E并再次扣职业人口；各开发量减少D(开发量,1000)，损失合计记R+FB；R+128加2，R+FF加2；调用建筑损毁0x3BB5B，返回损毁数量记R+103（13905..13B53）。属于轻度特殊工程/劳役状态，名称未冒称。
- R+11B==1：职业人口分别扣D(5*(R+24),1000)和D(R+24,100)，后者增加R+1E及主结构+A2；四开发量减D(5*开发量,1000)，汇总R+14B；R+12E加8，以0x8A70E概率判定完成，完成时R+11B=2、灾害字段R+5C=0（13DB7..1400D）。
- 灾害R+D7非零：类型1/2/4调用0x15647分别参数(1,5,8)/(2,5,8)/(4,5,4)，R+128加1；类型3直接加4；类型5调用(1,2,5)，加2；类型6清R+DE及R+D7。累计R+113同样增加。进度R+D8加原表[0,6,8,8,9,9,11]，传给0x8A70E概率判定，成立调用0x3B55E结束灾害（14017..14245）。类型1..5精确灾害名称需菜单/字符串交叉，不凭常识指认。
- 训练R+88>0时每半月减1（14248..14267）。中央训练开关0xCC9B5==1仅消耗一次，中央训练增加`D((官员R+0E*10 + 官员R+12*10 + 皇帝主结构+1F*4),中央士兵)+2`，中央无兵增量0，上限100（14285..14323）。官员+0E为武力、+12为忠诚的既有布局证据需按官员字段最终命名核对。
- 主结构+25C+i*2非零为待增援标记，清标记后，地区训练改为`D(oldTraining*oldSoldiers + pendingSoldiers*centralTraining,oldSoldiers+pendingSoldiers)`。随后中央兵/装备按主结构+B8+i*14的七个word扣除，地区士兵及六项装备同量增加（1436E..14614）。这是兵员与装备转移，训练按兵数加权；分母无零保护。
- R+CE不为0时，wealth += D(u16(R+CE),R+24)（分母非0），清R+CE并重新判贫富（14628..146BE）；可确认“待分摊入账/赈济额”。

## 建筑及工程记录：20条×15字节，0xCC9B8

13825末尾14707..14B63逐工程处理。记录结构：

| 偏移 | 类型 | 用途 |

| +0 | u8 | 地区号；255空闲/无工程；100撤销待清理标记 |

每半月执行`累计+=增量; 百分比=low8(D(累计*100,总需求))`；累计>=需求即完成。没有总需求0保护，百分比仅u8。

特殊设施完成时将皇帝主结构+28A+kind*2设2（14904），主结构+2C0增加模板表的一项（14923）；此处并非普通地区建筑。0xC505?表需与设施名称表联合解析，不应将20工程槽编号当种类编号。

建筑损毁辅助0x3BB5B：六项建筑（不含行宫）总量若非0，逐建筑数量调用概率0x8A70E；成功从六类随机挑一类，最多尝试29次寻找尚>0建筑，每次成功减1并计数。0x9AB62为rand候选（需主线验证），因此分布取决于rand和6取余，不能直接宣称均匀概率。

另一个93×7字节计时矩阵0xCC530由0x13630每半月更新：值100跳过；值>=3减1；**旧值2**调用0x14F20并清0，旧值1不推进。93行索引并非31地区，应单独核对任务/官员/命令映射，不能与20工程表混合。

## 开发、人口转业、民忠及军费辅助

0x3AFC7：R+9A=1..4指定行业开发量增加0x8A86D返回的开发效果，且钳到对应容量上限（R+28/2C/30/34）；该返回值由官员/任务规则决定，调用参数是地区ID和模式。0xCCC85非0时还生成返回值*10的float副本，但此函数主体的四开发写回仍使用原返回值。

0x3B0F9：迁移比例参数原始字节0xC8B24=3。CCC85非0时分母10，否则100；先分别算各职业转移人数D(n*3,denominator)，目标R+9B=1..4时另外三行业相应减少，目标增加另外三行业之和。总职业人口守恒，目标自身的转移量不使用。

0x3B637部分：体能减皇帝主结构+44*5并钳0；各特殊设施状态2的加成分别加到六项内政指标。民忠按R指针计算：

```
税率项=(50-tax)*2
官员项=(官员智慧<59)?0:D((智慧-59)*25,10)
平均指标=min(D(安定+治安+体能+营业+积粮+防御,6),100)
民忠=D(税率项*35 + 官员项*15 + (R+96)*10 + 平均指标*20 + D(贫富等级,4)*20,100)
民忠 += 皇帝主结构+2BE + R+94
民忠=max(民忠,0)
```

证据3B918..3BA74。贫富项真是先`D(level,4)`，所以0..3均为0，4才贡献20，再除100后影响很小；不要擅改为level*5。R+96/94业务名待UI验证。

0x3BA79：士兵=floor(总人口*R+136/100)写word，然后地区军费`D(士兵 + D((R+8A)*士兵,50) + D(训练*士兵,50),50)`，若0改1；R+8A未知（总人口之前的word字段）。这是非玩家地区按人口推兵数量的路径，不能套到玩家所有地区每旬自动征兵。

## 灾害损失子程序0x15647（追加恢复）

传入 `(主对象,地区,死亡千分比,转民夫千分比,开发损失千分比)`。

1. 死亡数=D(死亡千分比*(R+24),1000)，调用0x3B3DD从职业人口分摊扣除；累计到R+107（0xC9A13）。
2. 转民夫人数=D(转民夫千分比*(R+24),1000)，增加R+1E并从职业人口扣除；主结构+A2及地区R+10B同步累计。
3. 各行业开发量损失=D(开发损失千分比*开发量,1000)，原开发量扣减，四项合计累计到R+10F。

按13825调用参数，灾害1每半月死亡1‰、转民夫5‰、四项开发损失8‰；灾害2为2‰/5‰/8‰；灾害4为4‰/5‰/4‰；灾害5为1‰/2‰/5‰。类型3在此路径没有调用人口/开发损失程序，但每期产出累计扣4；“没有此子程序”不等于没有任何其他影响。

0x3B3DD职业人口扣减先把总量D(loss,4)平摊四行业，余数轮流从尚>0行业扣；某行业不足时存在先清0再读原值的机器码次序问题（3B42D..3B443等），可能把缺口错误计为整个均分份额。建议运行差分验证极端小人口场景，复刻器应忠于指令而不是仅理想平摊。

## 人口增长字面指令验证（2026-10-14复核）

`verify_population.py`使用主线calendar CPU的数值内存/寄存器辅助，补齐imul、sar、div/idiv，对KING 0x128BA..0x12A4F整个独立人口for循环执行，无系统/游戏调用；`population-verification.json`保留逐写入证据。3个有意义的跨地区用例通过：

- 税收循环最后财富变化=-40、两地区积粮20/80、民忠40、四职业初始各1000：两地区最终各职业1003，证实第二地区不按自己的积粮80计算。
- 最后财富变化=-40、三地区积粮20/100/20：最终各职业分别1003/1013/1013；中间地区把共享局部变量改100后，后方低积粮地区同样受影响。
- 最后财富变化=60、两地区积粮20/80：两地区各职业1010，证实结果依赖税收循环最后地区。

此验证检查真实机器指令序列的变量持久化、符号扩展与多次截断，不是理想公式单元测试。它没有验证DOS实际游戏运行、随机行为或此前税收循环是否受到异常字段溢出影响。
