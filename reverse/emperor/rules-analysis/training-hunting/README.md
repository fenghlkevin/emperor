# DOS《皇帝》修习增长、消耗与狩猎规则核验

日期：2026-10-16。只新增调查证据及验证脚本，未改现代游戏实现。

## 取证范围

使用同包 KING.EXE、EMPEROR.EXE、QUICK.EXE 的既有 LE 重定位映像和指令索引。包装默认 KING.conf 启动 EMPEROR，快速配置启动 QUICK。复刻普通模式以 EMPEROR 为基准；不得混入 QUICK 的加速收益。

## 四项修习（普通版 EMPEROR，与 KING 相同）

| 行动编号 | 场所 | 增长 | 特长加成条件 | 每次体力消耗 |
|---|---|---|---|---:|
|2|棋琴阁（项目称琴棋阁）|魅力|皇帝 E+0x27 == 0 时额外 +1|40|
|4|御书园（项目称御书房）|智慧|E+0x27 == 1 时额外 +1|40|
|6|百剧院（项目称百戏园）|才艺|没有对应加成判断|40|
|7|武道场|武术|E+0x27 == 2 时额外 +1|40|

E+0x27 由开局结果写入，是影响修习的三类倾向码；这里保留数值码，不擅自命名成未经界面核对的中文性格。

每次增长按以下顺序：

1. 取 `r1 = rand() % 100`。0..19 得1点；20..54 得2点；55..89 得3点；90..99 得4点。对应名义比例20%、35%、35%、10%；原随机数取模存在轻微偏差，不宣称严格均匀。
2. 再取 `r2 = rand() % 100`。若 `r2 < 年龄 - 10`，减少1点；随后基础增长至少为1。正常年龄内，20岁约10%的减点机会、40岁约30%、60岁约50%。10岁及以下不减，110岁及以上必减。
3. 棋琴阁、御书园、武道场按上表匹配倾向再加1；百剧院不加。
4. 最终能力封顶500，返回并显示实际增加值。

即：`基础 = max(1, 分档随机值 - 年龄减点标志)`；`实际增加 = min(500 - 旧值, 基础 + 特长加成)`。

普通修习范围1..4点；匹配特长范围2..5点；封顶附近可实际增加0点。画面的“勤奋专心／心有杂念”等文案来自同一基础收益分档，不是额外再抽一个成败概率。

四项修习没有直接附赠健康或快乐，也未在这些结算分支扣寿命。体力在完成回调扣40、最低截断为0；能力已满也不会免除消耗。不能将项目现有练武健康+10、百戏快乐+15说成原版行为。

## 快速版 QUICK 的实质差异

QUICK 基础分档改为：0..14得3点、15..39得4点、40..69得5点、70..89得6点、90..99得7点，名义比例15%/25%/30%/20%/10%。年龄仍按 `rand()%100 < 年龄-10` 减1，但无普通版的最低1修正（自然范围最低2，故无需该修正）。匹配上述三个倾向时额外+2，才艺无倾向加成。四项体力仍各扣40。

因此 QUICK 可出现基础2..7、匹配倾向4..9的收益，不能把它的数值与普通版混用。

## 狩猎

完整命中、目标权重、季节表及版本地址见 [hunting.md](hunting.md)。普通版 EMPEROR/KING 每场60秒、30箭：目标权重1/2/3分，累计S；最大体力 `+floor(S/4)`、封顶500，当前体力不随上限增长而增加；健康固定+20、封顶100；不扣当前体力，不增加武术或快乐；扣剩余寿命8，特殊全局标志为1时按既有小额寿命扣减规则乘12。

QUICK 的最大体力收益为 `floor(S/3)`，其它所列结算参数相同。零命中仍增健康、扣寿命，上限收益为0。原版显示“射中几只”，但上限收益实际取加权得分，并非简单只数。

## 对当前项目的影响与实施顺序

当前 `src/emperor.mjs` 四维封顶100、固定+5、消耗1；截图体力上限10。这套量纲不能仅把扣1改为扣40：会导致现有存档一次修习即耗尽。实施时需将四维上限、初始/旧档体力尺度、修习公式、恢复活动与数值说明一起调整，并排查读取皇帝四维的招募/政务逻辑，避免改成500后下游失衡。

狩猎应独立结算“当前体力”和“最大体力”；尚未实现狩猎交互时不能用普通修习代替。以上为实施影响分析，不是新增原版规则。

## 剩余边界

本次所问收益和消耗已在普通版及快速版指令上定位。尚未做 DOS 界面前后存档受控实测；时间推进、取消/中断、极低体力进入时的全局调度与所有疾病恢复路径没有在本轮全面复验。E+0x27三个倾向的中文界面名称未强行补写。特殊寿命标志也不擅自命名为“难度”。
