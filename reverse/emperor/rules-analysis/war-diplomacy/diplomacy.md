# 外交操作补充：真实UI事件路径与整数规则

以下均为EMPEROR静态VA。与主报告一致，地区完整对象R=0xc99ac+i*337。本篇除特别说明外使用**R相对偏移**，区别于主报告以R+2为数据起点的偏移。新文本证据来自EXE数据对象的Big5字符串及消息指针表0xc71ec，原始文本及地址保存于diplomacy-messages.json。

## 实际外交菜单和事件分发

`0x45a4f..0x482f3` 为外交界面消息处理器，使用对话对象D的操作word+0x34、条约种类word+0x32、态度byte+0x4f、成功word+0x52、各子窗口指针进行多轮事件分发。跳转表0x47244的六个条目对应：0缔約、1解約、2貿易、3和親、4進貢、5勒索。对象D+0x5c起各byte标记该操作已使用；成功结算后置1，并与菜单禁用状态合并。这些标志生命周期是当前交谈，不应写进地区存档。

选择国家时 `0x46af2` 将R+0xbe(VA0xc9a6a)写1，可确定为外交接触/访问标记，具体长期效应须继续追xref。

## 条约的真实成功判定

选中目标后，在0x46b35读取皇帝E+0x2cc到D+0x54，读取目标R+0x12f(VA0xc9adb)到D+0x58。前者为0x39bde计算出的军力指标，后者为外方军力/威慑基数。E+0x2b8是交涉威望指标，其UI标签由总字段表对照。

令F=目标友好度、P=威望、M=中国军力、K=目标军力，则0x473d1算：

```text
B = T(F*F * T(P*M/K) / 10000)
```

这里先P*M/K再乘F²；使用32位signed IMUL及IDIV，乘法溢出时只保留低32位。之后threshold以**signed16**截断传入random gate。

|条约D+0x32|真实文本|阈值|成功结算友好变化|关系矩阵[30] / 国别状态|
|---|---|---|---|---|
|1|互不侵犯合约|s16(B)|+2|后续关系刷新函数按条约种类写值|
|2|防御同盟合约|s16(2*B)|+5|同上|
|3|保护条约：中国保护外方|s16(T(s16(B)/20))|+20|3 / 4|
|4|被保护条约：外方保护中国|**直接接受，不抽随机**|+30|4 / 3|

证据0x47443/0x47480/0x474bf/0x47506。保护条约的除20输入先s16(B)，这是容易漏掉的截断。签约只是设置success=1并呈现接受文字；用户随后实际确认，0x46527..0x466cd才落实友好度和保护关系。签约失败在0x4756a显示“我國不接受”。

R+0x12d(VA0xc9ad9)在签保护条约时写1；结合定期保护费路径，它是相关一次性/周期事件标志，其更准确中文标签待每回合路径核对。

中国军力计算0x39bde：遍历**i=0..30含31个地区**且R+2!=0的地区，

```text
A = T(2*Σ(头盔+皮甲+皮盾)/3)
B = Σ T(训练*士兵/50)
M = T((A+B+E[0x9e])/50)
```

因此不是“军力=总士兵”。E+0x9e的军事总量项应由总表命名，本篇保留偏移。敌方军力字段R+0x12f未找到普通更新写，仅构造、载入和存储，可能为既定基数。

## 开始贸易：态度门槛及前期亏损

0x47008按态度0..4分支：0要求输入额度，1/2同样要求输入额度，3/4显示“不想跟你们做贸易”并结束该操作。因此正常友好度门槛是**F>=41**。它不是按概率接受。

`0x47836` 对操作2，将输入signed16写R+0xb0(VA0xc9a5c)。没有找到这一操作把利润率重置；初始构造0x3ad42设置R+0xb6=-20。主报告半年结算累积利润率公式因此造成正常前期亏损。

固定F=99、额度1000的十次独立半年结算样例（忽略自然友好度变化）收入：-160,-120,-80,-40,0,40,80,120,160,200。不能说第五次结算必回本：第五次只是当年利润0，累积损益还为-400，第十次累积100，盈亏平衡取决于友好变化、额度变更和是否曾清零利润率。

## 进贡与勒索

进贡操作4，0x478e5把用户参数先解释为signed16 A，再存D+0x47。友好度 `F+=T(A/2000)` 后钳制0..99，总资金E+0x45减A、外交/亏损支出账E+0x71加A。**没有成功随机判定**。友好变化发生在态度文案选取前，所以一次进贡可能提升文案档位。金额>20000与<=20000显示不同感谢/讥讽文本，但这不改变增益公式。金额1999→+0、2000→+1、32000→+16。

勒索操作5，0x47a9d解释输入为signed16 A存D+0x4b，默认success=1。态度0、1、2保留成功，态度3、4清0：正常友好**F>=41必接受，F<=40必拒绝**，不是军力/随机判定。成功总资金E+0x45加A、其他收入E+0x4d加A、友好减T(A/1000)；失败友好减5。金额999→成功友好不变、1000→-1、32000→-32，均经0..99钳制。该结算路径不扣外国现金字段，不能假设双方金钱守恒。

输入范围取决于输入窗口构造；若修改器或不合法事件传A>=32768，signed16会变负，行为可能反转。报告没有把这些异常输入当正常玩法。

## 和亲

在外交菜单初始化时扫描子女列表，要求子女byte+9=1（女性）、年龄byte+8在**16<=age<29**，才启用和亲（0x45f7a..0x45fb1）。年龄16包含、29不包含，不能写成笼统“16至29岁”。

操作3选择公主后，0x47611按子女ID匹配列表；根据态度显示接受文字0x49/0x4a/0x4b。确认事件参数为1后，0x47ead进入执行：友好+30，调用0x7ea43删除/移出该子女记录，并记入事件历史。没有在该确认路径发现概率判定。若未确认则按態度文案处理，具体拒绝惩罚路径与原始消息49–4e保留于dispatcher片段。

这说明此路径以年龄/性别筛选和用户确认为主；没有证据支持“公主美貌决定概率”。

## 解除条约

解约时根据条约类型显示不同告别文案，确认后0x47e56将关系矩阵[30]清0、国别状态清0。执行前0x467b9读取表0xc8bd4，按原条约类型扣友好：原始五字节 `[0,3,10,27,45]`，即非侵犯-3、同盟-10、保护-27、被保护-45，随后最低0。

对应高风险文案是否最终发起战争应沿后续事件链确认，**一句“将发动战争”的文案不足以证明当场开战**。原主报告没有用该文字替代代码证据。

## 自动侵略候选的计算和16位细节

自动战争候选选择0x80969..0x80a1a，对已筛选候选国计算：

```text
Q=T((101-F)^2*K/M)             # 32bit乘法和除法
H=T(s16(Q)/1000)             # 原程序此处CWD / IDIV BX：16bit有符号
```

取H最大的候选，必须H>=1，随后调用random gate(H)。所以正常无溢出时低友好/高敌军力/低我军力均提高风险；**分母M=0会触发原程序除零**，没有这段的保护分支。

不能写作“每国独立按H%发动战争”：实际选出最大H后只抽一次，且候选筛选受地理和关系状态约束。低16位截断可使很强敌人Q>=32768成为负数，从而不被选中；需动态确认异常军力范围是否实际出现。

## 随机数规则及算数验证

0x9ad72执行LCG：`seed=(seed*1103515245+12345) mod 2^32`，返回 `(seed>>16)&32767`。seed存VA0xc9030。0x8a7fe使用 `random%100 < s16(threshold)`，边界threshold=0必失败、100必成功；若均匀假设32768种返回值，余数0..67各328次、68..99各327次，因此“百分比阈值”有轻微取模偏差。

`verify_diplomacy.py` 在全部32768种rand返回值上核对边界计数，验证signed16转换、保护条约内层截断、军力指标、首年负利润和临界年龄/额度/勒索输入。它验证的是逐指令重建的静态算数模型，没有运行DOS游戏。

## 保护费、友好自然增长和外国贡品

半年结算0x123fe的0x13059..0x130fe对非统治地区执行保护费：

- 关系状态3：中国收取`2*目标地区R+0x24`，进入其他收入E+0x4d和总资金E+0x45。
- 关系状态4：中国支付`2*全国人口E+0x2f`，进入外交支出E+0x71并从总资金扣除。若有多个此状态国家，该笔全国人口费用在循环中按国家重复计。

R+0x24是**农牧商工四职业合计人口**，由实时汇总函数0x388ba重算，不是外国总人口R+0x8c。E+0x2f由统治地区职业人口、E+0x9e军队/特殊劳役量及E+0x96中央民夫合计。保护费不受贸易额度/利润率影响，也不是贸易利润的一部分。

同一半年结算0x12420读取关系状态增长表VA0xc8bdc，原始七字节 `[0,1,2,2,2,0,0]`；只对非统治且关系状态非0的国家加友好，最高99。因此非侵犯+1、同盟/保护/被保护+2，战争无增长。这是**半年**变化，不是每半月都+1/+2。

外国贡品函数0x83bea由事件dispatcher `0x7f871` 的事件51（表0x80540第50槽→0x804cb）调用。事件阶段表VA0xc82ce中该项第一word=0，需当前阶段c98df=0才执行。未直接将它的概率叫作每月概率，因为实际可调用频率取决于dispatcher与半月流程。

贡品计数R+0x12d(VA0xc9ad9)在每半月推进0x14d07中，非0时按byte加1；保护条约签订时写1。贡品函数按地区顺序检查非统治地区：

```text
if count>=25:
    count=1
    choose_this_country
else if F>=90 and random%100<2:
    choose_this_country
else continue
```

所以**F=90包含**；25半月计数触发的是强制贡品，计数从1开始，经24次递增达到25，约一个游戏年。只能择中扫描顺序最早成功的国家；多个国家不会在同一函数独立各送一份。此入口不检查关系状态5，因此不能仅凭直觉认定战时绝无贡品。

选中国家后写皇帝E+0x2bc为来源国家，抽random%100：

- 小于30：美女贡品，E+0x2ba待安排美女数若<4就+1，且E+0x2bd=0xff；计数已4时仍返回美女事件但不增加数量。
- 否则：药材贡品，随机种类`random%8`，E+0x2bd存药材ID，对药材库存数组VA0xccbc8、2字节stride的**低byte**+1（字节溢出不向高byte进位）。

相对主入口30%美女/70%药材；8种药材的rand%8均分32768种返回值。贡品来源判定无须假设“友好必须大于90”或“只有藩属能送药”。

另外未择中国家的回退支路，会在phase-half标记c98de=0时把皇帝E+0x94（候选贡品概率累加计数）加5并作概率判定，随后试图找F>=80的国家。**该分支循环增加局部计数，却读取已跑到30的D+0x2b，而不更新它，静态看似只反复检查地区30**。因此本篇没有把回退支路美化成“从所有友好80国家随机挑选”；完整证据在foreign_gifts.asm的0x83d92..0x83ed9。后半段同样送美女或随机药材，但其选国细节存在疑似编译/原程序bug，需动态重放确认。
