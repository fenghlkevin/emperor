# 皇帝、后宫与子女生命周期

本报告是 KING 重定位汇编和程序内原始文字/常量的静态复核。明确业务名已有文字与字段操作的证据；尚未以 DOS 运行时受控对照验证。地址为虚拟地址，`E+offset` 指 `[0xC9810]` 指向的皇帝运行时记录，不能直接作为存档偏移。

## 皇帝字段及年龄宽度修正

| 业务字段 | 运行时 | 磁盘绝对偏移 | 宽度 |
|---|---|---:|---:|
| 年龄 | E+0xE | 24 | 1 |
| 寿命上限 | E+0x13 | 26 | 2 |
| 剩余寿命 | E+0x15 | 28 | 2 |
| 最大体力 | E+0x17 | 30 | 2 |
| 当前体力 | E+0x19 | 32 | 2 |
| 智慧 | E+0x1B | 34 | 2 |
| 武术 | E+0x1D | 36 | 2 |
| 魅力 | E+0x1F | 38 | 2 |
| 才艺 | E+0x21 | 40 | 2 |
| 健康 | E+0x23 | 42 | 2 |
| 快乐 | E+0x25 | 44 | 2 |

存档24字节是单字节年龄；25字节是独立状态。旧解析器的`age_candidate=u16(24)`误合并状态，已修正为单字节，并保留`state_byte_25`。加载函数 0x91DDF–0x91E92逐字段复制提供磁盘映射。

字段名称来源不是修改器绝对地址猜测：程序指针表0xC7984..0xC79A4按顺序指向“體力增加%d”“壽命增加%d”“最大體力增加%d”“智慧增加%d”“武術增加%d”“魅力增加%d”“才藝增加%d”“健康增加%d”“快樂增加%d”，初始化至0xCDB20..0xCDB40。药效函数对应调用体力0x393AF、寿命0x39472、最大体力0x39414、健康0x39693、快乐0x396EB，再使用上述文字打印实际增加量。上限字段由相应辅助函数的比较/截断确定。

## 体力、寿命、健康的变化

正常小数值范围内，辅助函数的公式如下（磁盘2字节运算，异常修改值可能发生16位溢出，不能当任意精度数值）：

- 增加体力 `current=min(maximum,current+delta)`，返回实际增量：0x393AF–0x39414。
- 增加最大体力 `maximum=min(500,maximum+delta)`：0x39414–0x39472；不会在此函数自动同比增加当前体力。
- 增加剩余寿命 `remaining=min(limit,remaining+delta)`：0x39472–0x394CF。
- 增加健康/快乐分别在100封顶：0x39693/0x396EB。
- 扣体力在0截断；体力不足时 E+0xF设1、E+0x10清0：0x397D1–0x39837。0x1178C也在体力恰0时设置该状态。因此它关联过劳/休克恢复流程，不能把此状态当死亡标志。
- 扣健康在0截断；健康不足时 E+0xF设2、E+0x10清0：0x398A3–0x3990B。
- 扣剩余寿命在0截断：0x39837–0x398A3；**若全局0xCCC85==1且扣值<10，则先乘12**。此模式标志的具体界面选项尚未独立定位，不将其命名为难度。

剩余寿命耗尽的处理在0x31C18：检测E+0x15==0，按年龄<=29、30..49、50..64、65+写E+0xF为0x86/0x87/0x88/0x89，E+0x10设1并进入后续流程。这是寿命归零导致终局状态的直接证据。现有存档中寿命被改成9999等值，故不能从样本反推原始寿命自然下降速度。

程序0x86F90–0x86FB2用于对寿命估计：`年龄 + trunc(剩余寿命/48)`。这个48为程序自己的年换算常量；不应把它等同“每年必扣48”的已证实回合规则。寿命扣减来自各行动/事件，不能用单一不变的年扣量覆盖。

休息行动分支3（0x8D258）先增加健康5；状态0时增加体力150，若行动段计数0xC9843==2再扣寿命2。状态1时将体力补满、扣寿命30，状态2也补满、健康加80、扣寿命30；后二者将状态加10进入恢复流程。上述扣寿命仍经过全局特殊×12规则。这里只描述代码分支，不把“休息一次必扣固定寿命”推广到所有状态。

临幸行动计数 E+0x2CA在行动选择1时++（0x118C9），其它若干行动清零（0x119A7、0x11CB8）。创建临幸界面0x8CD8A..0x8CDF9读取此计数，0..6对应扣寿命 `[0,2,4,8,16,24,32]`，>=7时计数截到7、扣35。若0xC9843==2另扣3；快乐加5。因选择1先自增，正常第一次按索引1扣2，而不是表索引0的0。是否每种取消/中断路径都会清零仍须运行时验证。

临幸体力恢复（0x8CFBE..0x8D058）：已有后宫对象计算 `trunc(外貌²/40) + 经验 + slot_bonus[名分槽]`，写入后宫能力，再经验++；将该能力增加到皇帝当前体力并按最大体力截断。新遇女子的另一分支只有 `trunc(外貌²/40)`。这解释了能力为何需要在临幸时重算；不是所有存档的能力都必然满足某个初始公式。`slot_bonus`位于0xC8134，原始34项中槽0..4为50，5..13为20，14..33为5。

药物某些效果直接按年龄计算寿命增量，例如0x6EF16、0x6EF68、0x6EFBA为 `trunc(800/年龄)`、`trunc(3000/年龄)`、`trunc(1500/年龄)`，再受剩余寿命上限约束。相关药物种类枚举尚未在此报告完整命名，不能仅按分支顺序指认药名。

## 怀孕与出生

后宫运行时步长19；磁盘步长24。关键字段：磁盘+9/runtime+9为年龄，磁盘+15/runtime+16为怀孕月计数，磁盘+16/runtime+17为老年死亡概率累计量，磁盘+17/runtime+18为肖像ID。

受孕路径0x10D45–0x10DCF读取当前后宫索引E+0x12；要求女方年龄 **15..35，包含两端**（原始常量0xC8B0A/0xC8B0B），依次通过20门限随机检查与皇帝年龄门限检查，成功将怀孕计数置1。

| 皇帝年龄 | 第二次随机门限 | 两次通过率的理想近似 |
|---|---:|---:|
| <20 | 90 | 18% |
| 20–29 | 100 | 20% |
| 30–39 | 80 | 16% |
| 40–49 | 50 | 10% |
| 50–59 | 20 | 4% |
| >=60 | 5 | 1% |

年龄门限函数为0x8A7A8；概率函数0x8A70E实现`rand()%100 < threshold`，不是浮点概率；表中百分比是假定随机余数均匀且两次调用独立时的近似，保留模偏差。后宫菜单0x30BC3/0x30DAF/0x30FA9/0x311A1分别检查各名分组，未占用或已有非零怀孕计数的选项走禁用绘制分支，支持正常界面避免对怀孕女子重复受孕。

每月更新0x120C7内遍历34槽，只要怀孕计数非0就++，不另检查存在标志（0x12177–0x12189）。出生检测0x824E9遍历34槽，首个计数>=11者清为0，保存母亲名分，`50门限检查`结果作为孩子性别标志，母亲能力减20并在0截断，皇帝快乐+10，返回一个事件。上层0x7F9A2触发事件16；该调用一次只返回首个符合条件者，多个同时到期的处理顺序由外层事件扫描决定，不宣称同一函数一次全部生产。

受孕时计数1，经过10次月更新达到11，因此应理解为“十次月结算后满足出生条件”，不要按数值11误写成怀孕11个月。出生不是月更函数直接插入孩子；它通过出生事件/命名界面。0x7F4B6要求命名界面回调码0x65才完成创建：分配18字节记录，设置年龄1、复制性别标志、复制母亲名称，追加至子女链表0xC98F8。取消或未完成命名的其它路径不能只依据已经清零的计数认定新孩子必已入存档。

子女磁盘+7是年龄（runtime+8），+8是性别标志（runtime+9），**0男、1女**：子女界面0x6A419读取runtime+9，乘4索引0xC5048；对象2里0xC5048指向“男”、0xC504C指向“女”。解析器新增`age`/`sex_flag`/`sex`，未知枚举原值照留。外交和亲扫描要求该字段1，与公主条件相符。

## 年龄与老年死亡事件

年龄增加在年度0x133C8，不在每个半月、每月或每次行动：

- 皇帝E+0xE++。
- 34个后宫槽的年龄全部++（包括未占用槽，因此空槽旧字节不能当真实人物）。
- 官员链表逐节点runtime+11++（0x2E92E），对应磁盘+9。
- 子女链表逐节点runtime+8++（0x7E8B9），对应磁盘+7。

均为单字节自增；异常255岁会按机器指令回绕，代码未在这些增龄函数中截断。

后宫死亡检测0x827D9：只有存在标志非0且年龄>=60的槽有资格；每次资格检查在runtime+17（盘+16）加2，然后调用`rand()%100 < 累计量`。成功则清存在标志，皇帝剩余寿命扣2、快乐扣10，并返回首个事件。累计量是u8，未在此函数封100，异常长时间不触发也会回绕。**+2发生在事件检查，不应未经外层调度验证写成每月+2。**

子女死亡检测0x8290C：年龄>=60的链表节点runtime+17加2并用同样随机门限；成功删除节点、皇帝寿命扣1、快乐扣20。runtime+17未见子女读取函数复制，是记录末尾运行时状态；磁盘子女+16..20仍是未命名原始区，不应擅自将盘+17命名为该概率。

另有皇帝年龄>=35触发的家庭长辈事件0x8268C，以及皇帝年龄>=60且皇后存在时的0x82730；各自累计概率+2并扣寿命/快乐。前一事件的具体人物关系尚未依据界面文字独立命名，后一事件不能等同按皇后自身年龄判死，因为代码明确用皇帝年龄。

## 复现与尚未完整覆盖

运行 `python3 reverse/emperor/rules-analysis/lifecycle/extract_evidence.py` 导出25段地址精确的汇编与`evidence.json`（寿命/健康及子女性别中文指针、年龄界限、临幸消耗表、存档实际值）。存档解析器保留全部原始字节并新增已证字段，不改原档。年龄、寿命、怀孕、出生、年度增龄已按证据恢复；全部疾病事件、药物枚举、每个事件检查调度次数、特殊模式标志与异常存档兼容仍未完全验证。

## 读档恢复是否推进回合

KING UI0x2BBDE在读取模式调用0x2BD7F；该包装先把全局0xC9884所指控制对象word+0设1，再调用0x91B6F读档。读档调度自身只读取前缀、8组数据并关闭文件，没有调用推进到下月的0x13485。

之后主循环0x101EC在0x10432检查这项标志等1，0x1045C执行0x13825（地区及事件状态更新），0x1057F取控制对象word+2的保存行动，0x105B2调用0x1187A恢复该行动界面，0x105BF清word+0，避免每次主循环持续重复这个恢复分支。

该路径**没有直接调用0x13485，也没有直接把年/月/半月字段自增**；但确实再运行一次0x13825，因此不能称为完全无副作用的状态恢复。其地区计时、生产或事件更新的影响，应结合内政/回合报告与受控模拟核验，不应凭攻略断言“读档必进一个月”。某些恢复行动会运行自己的构造逻辑并修改数据，例如保存行动1恢复临幸时可再次自增计数/扣寿命；这属于所保存行动的分支副作用，不能概括为所有存档必发生同一种变化。
