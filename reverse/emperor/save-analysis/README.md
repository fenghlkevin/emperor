# 皇帝存档结构与原始数据

本目录分析游戏安装包自带的 KING1–5.SAV；不修改原存档。JSON 内 `raw_hex` 和每个表记录的 `raw_hex` 保留所有字节，`*_bytes.csv` 提供逐字节原始值。字段带 `_candidate` 的业务含义仍需要游戏界面或调用点验证，不能等同原作者源码。

## 已用主程序反汇编核实的序列化框架

以下地址均为 KING.EXE LE 对象重定位后的静态地址，依据 `../code-analysis/KING/object1.relocated.asm`。

| 存档内容 | 格式 | 反汇编依据 |
|---|---|---|
| 前缀与皇帝/全局数据 | 10 字节前缀 + 746 字节固定块 | 根任务识别的读取入口 0x91D70 |
| 官员数量 | offset 0x2F4，2 字节 | 0x92533 读取2字节数量 |
| 官员记录 | offset 0x2F6，数量 × 47 字节 | 0x9255F push 0x2F，循环按数量递减 |
| 后宫 | 34 × 24 字节 | 0x926B4 cmp 0x22，0x926BD push 0x18 |
| 子女 | 2 字节数量 + 数量 × 21 字节 | 0x9280F push 2，0x9283B push 0x15 |
| 地方/国家记录 | 31 × 370 字节 | 0x928E9 cmp 0x1F，0x928F2 push 0x172 |
| 其他链表记录 | u8数量 + 数量 × 1793字节 | 0x934D1，32次分块读取，现有数量均0 |
| 5字节链表 | u16数量 + 数量 × 5字节 | 0x9398C |
| 固定尾部 | 1523字节，具体划分见下 | 0x93AB8 |
| 未消费冗余尾 | 肖像使用标志的前13字节 + 全20字节副本 | 游戏保存明确写出，加载不消费，见下 |

存档结构不是直接的内存 struct dump。官员加载分配37字节运行时记录，后宫运行时步长19字节，子女分配18字节，地方运行时步长337字节；磁盘记录分别是47、24、21、370字节。主程序复制特定字段并跳过磁盘预留区。官员容器是链表（节点 +8 为下一节点），子女也是链表。`layout_evidence.json` 提供逐条复制证据：磁盘字段偏移、宽度、运行时偏移、加载/存储指令地址。地区识别了116条标量复制（数组重复项包含在内），新增movsx映射明确贸易收入磁盘2字节扩展为运行时4字节；已关联业务字段见第二轮字典。

## 人物字段

官员磁盘偏移0..6：BIG5名称和NUL终止符；+7、+8各1字节；+9年龄候选；+10/+12/+14/+16/+18分别为智慧、武力、清廉、忠诚、经验候选（均2字节）；+20/+21/+22各1字节，运行时分别存至+20/+1/+0；+23以后已识别其他整数复制，详见布局证据。例 KING1 李善长：48岁、90/23/80/99/99。业务名来自攻略且与数据范围一致，但仍标候选。

后宫+0存在标志，+1..7 BIG5名称，+8候选入宫序号，+9年龄，+10外貌，+11经验u16，+13能力u16，+15怀孕候选是 **单字节**，+16独立单字节，+17肖像。未占用槽名称可能残留旧内存，例如KING1大量槽含不完整人物名称，必须结合存在标志解读。皇后能力初值600不符合攻略普遍能力公式，不能将该公式无条件应用到每个槽。

子女名称0..6，+7为单字节年龄、+8为单字节性别标志（0男、1女，由界面文字指针表核实），母亲名称从+9开始。现有两名子女原始文本为“朱標”和“朱帝”（名称中有额外原始字节，JSON保留，不能自行纠正为历史人物名）。后宫+15已确认为月怀孕计数、+16为老年死亡概率累计量、+17为肖像ID；新增语义字段仍保留旧原始字段，详见 [生命周期复核](../rules-analysis/lifecycle/README.md)。

皇帝年龄位于存档24，宽度1；存档25为独立状态字节。已修正旧解析器把两者合并为u16的问题。存档26/28为寿命上限/剩余寿命，30/32为最大/当前体力，34/36/38/40为智慧/武术/魅力/才艺，42/44为健康/快乐；各宽度2。这些命名由游戏药效中文字串、操作函数及读取复制独立关联，并非修改器地址套算。

地区目前只能确定31条结构相同的记录；第31条主要经济值为0且前两标志为1，可能代表中央，但不能仅凭数据断言。每条+328处float32初始值为1.0，其他字段宽度取主程序复制指令，CSV中的 all_u16_le 只是方便检索的机械视图，不代表全部字段都是u16。

## 攻略复核结果

用户攻略为GB18030文本，而存档人物名称为BIG5。攻略绝对地址只适用于其示例状态：新增一个官员会导致后宫及后续部分整体后移47字节。攻略的后宫地址表存在交替25/23字节错误，真实磁盘步长固定24。其药材0x3AAC比KING1初始药材候选位置0x3A7D多47字节，不能直接套用。金钱72十进制与KING1该位置的1000000吻合，尚保留候选命名。攻略是参考材料，未执行其中修改游戏数据的说明。

## 复现

```sh
python3 reverse/emperor/save-analysis/extract_layouts.py
python3 reverse/emperor/save-analysis/extract_tail_layouts.py
python3 reverse/emperor/save-analysis/parse_saves.py
```

解析器只依赖Python标准库；每个JSON逐字节反转为原存档并检查完全相等。三份完整存档导出官员208条、后宫102槽、子女6条、地区93条；所有未知字节均被保留。当前结果覆盖全部原始存档数据，但没有宣称全部字段业务含义已完成还原。

## 尾部进一步还原

`tail_layout_evidence.json` 由各读取调用提取长度与目标地址证据。`tail_sections.csv` 按磁盘顺序列出各块偏移、长度、原始值及读指令地址；`herbs.csv`、`array12.csv`、`array15.csv`、`list_a.csv` 分表导出。

其他链表每条记录读取32块，合计1793字节；运行时分配1796字节，节点8字节，下一节点在+4。大数组两次各810字节，但数据不会直接对应整个运行时连续区域，末尾多个u16读取均覆盖运行时+0x702，应按读取指令顺序保留这些独立磁盘块，不能合并覆盖。没有包含此链表记录的现有样本，该分支仅由代码核实。

5字节链表数量在KING1/2/3中为0/6/22；运行时每节点9字节，前5字节数据，+5下一节点指针。

固定尾部依次为：u16、8×u16药材候选、30×12字节数组、20×15字节数组、四个u8、100字节、30字节、651字节、六个u8、u16、u8、u16、20字节、两个u8、20字节、三个u8、4字节。总长1523字节。数组业务含义尚未确认。

KING1/2/3的该读取序列分别终止于16494/18545/18719，距离文件末尾均33字节。进一步追踪KING、EMPEROR、QUICK写出函数已核实：末尾33字节重复正式区20字节后宫肖像使用数组的前13字节，再重复完整20字节。三份存档均逐字节匹配。正式区数组的KING运行时地址为0xCC4D8，控制后宫肖像随机选择时避开已用项。证据与复现见 [尾33字节核实](../rules-analysis/tail33/README.md)。

解析器保留`raw_hex`、`trailing_hex`和加载器终点`parsed_end`，新增`harem_portrait_used`与`redundant_portrait_tail`。后者列出两个副本原始字节，并报告`matches`、`differs`、`missing`或`incomplete`；不强制用户提供的存档副本一致。33字节后更多原始数据另存`extra_bytes_hex`。不能仅据副本不同判定存档损坏，因为当前加载代码不消费这些副本。


第二轮已增加20×15工程的地区/种类/每期投入/总需求/累计进度，以及1793字节战斗记录内两组45×18部队解析。自带存档战争列表为空，已用严格按观察保存位置构造的合成记录验证动态边界；没有把合成样本声称为真实战役存档。详见 `../rules-analysis/README.md`。
