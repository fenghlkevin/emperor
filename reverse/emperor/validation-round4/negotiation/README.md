# 招降、停战的精确概率与 DOS 断点设计

本文件是 EMPEROR 静态指令恢复和独立预测，不把预测标成动态通过。动态结果应引用主线 runtime 输出。VA 为原重定位地址；本轮 DOS 映射代码 VA+0x1D0000，数据 VA+0x1C6000。

## 原始概率函数

完整函数 `8A7FE(dummy, threshold)` 可直接调用，没有 UI；dummy 参数未使用。`9AD72` 的状态在 `C9030`：

```
seed = (seed * 0x41C64E6D + 0x3039) & 0xFFFFFFFF
rand = (seed >> 16) & 0x7FFF
roll = rand % 100
success = roll < signed16(threshold)
```

判断为严格小于（8A82D..8A831）。即阈值0必失败、1仅roll0成功、99仅roll99失败、100及以上必成功，但仍消耗一次随机数；负阈值失败且也消耗一次随机数。该函数返回 EAX=0/1，使用方多只看 AX。

若把每个15位输出等概率考虑，roll0..67各有328个原值，68..99各327个。阈值 t 的精确比例是 `(328*min(t,68)+327*max(t-68,0))/32768`，先把 signed16(t) 钳至0..100。它并非精确整数百分比。例如20为20.01953125%、99为99.0020751953125%。这是输出空间计数，不是声称某个有限种子样本具有相同比例。

[seeds.json](seeds.json) 给每个roll0..99找到一个确定初始种子；[predictions.py](predictions.py) 可复现种子和1111个边界预测。

## 正常比例范围的完整条件

先调用85A60重算双方加权军力，再 `raw=floor(100*P_A/P_B)`；P_B=0时raw1000。比较用 `r=signed16(raw)`。

招降：

|选项|条件|随机阈值|
|---|---|---|
|0 割地|r<75|floor((75-r)/2)|
|1 藩属|r<100|100-r|
|2 赔款|总是成功|不调用随机|

r74的割地阈值为0，即使通过r<75外层，也绝无成功；r72、73的阈值均为1。初稿把r73也列为0属于算术文字错误，预测代码与DOS结果均为1，现已订正。r99藩属阈值1，r100直接失败且不消费随机。

停战 direction=B+12：

|选项|direction=0|direction非0|
|---|---|---|
|0 无条件|r<100直接成功|相同|
|1 互不侵犯|r<75直接成功|失败|
|2 防御同盟|r<90直接成功|失败|
|3 敌藩属|r<75，gate(2*(75-r))|失败|
|4 敌赔款|r<90，gate(2*(100-r))|失败|
|5 我贡金|直接成功|r<=110直接成功；111..199 gate(220-r)；r>=200 gate20|
|6 我藩属|同5|同5|

特别边界：option3 r25阈值100仍消费随机；r26阈值98；r74阈值2；r75不抽。option4 r50阈值100；r51阈值98；r89阈值22；r90不抽。option5/6 r111..120阈值109..100仍必成功，但与r110不同会推进seed；r121阈值99；r199阈值21；r200及以上阈值20。

## 溢出边界

双方军力各自累加到word，比例计算后也只保存word。raw>=32768时变负数参与比较，因此极端军力会反转判断。例 A40000/B100→raw40000→r-25536。r=65535→-1。不能把公式当无限精度真实比例。

阈值也以word传给signed16比较。因此对异常负r，`100-r`及`2*(100-r)`等仍要再做signed16；不能只用概率钳制100。预测脚本保留此行为。此范围应与正常游戏数值范围分开标注。

敌方主动要求我方投降的5E686分支也用signed16比例：r<=100不抽而选择赔款；r>100依次抽 `t=floor((r-100)/4)` 的割地、藩属，第二次只在第一次失败时抽，最后赔款。t>=100（正常r>=500）必选割地。连续两次由同一LCG给出，并非数学上可直接假定独立；应记录具体种子和两次输出。direction=0跳过整段选择UI。

## 不修改机器码的 DOS 验证入口

使用原始程序CS/DS/SS环境，分配至少0x440局部空间。EBP设在已留出的模拟帧；ESP低于EBP-0x440。写 `[EBP+14]=W`；W+5D=B。W和B是测试fixture，不以自制代码替换被测算法。

- 招降：EIP=5F611，W+5B=option；断点5F739（在任何消息UI前），输出word[EBP-10]为0失败、1割地、2藩属、3赔款。原入口会执行85A60和真实PRNG。
- 停战：EIP=5FD48，[EBP+1C]=option，B+12=direction；断点5FFDF，输出word[EBP-358]为成功0/1。W+11D记录选项。
- 敌方主动招降：EIP=5E686，direction非0；断点5E7A3，W+5B为选项0/1/2。该段会改W+11B bit2。
- 只测概率门：完整call8A7FE(dummy,t)最小且可覆盖所有roll与阈值。

所有45槽默认typeFF；A槽起点B+65、B槽B+3CE，步长18。使用每侧一槽N=P、训练0、防御0，即85A60给军力P。N被movsx读取为signed16，结果累加到word；因此该简单输入的输出低16位仍为P。普通场景应把每队N控制在0..32767，极端总军力可分多队实现。设B军力100，A军力r即可实现正常整数比例r。分母0及raw溢出另建场景。

为避免UI分支中断，以上是有明确上下界的原机器码片段，并非完整游戏点击流程；动态报告应保留入口、终点、输入seed、实际roll、seed推进次数和结果。

## 成功副作用与 UI 边界

停战成功先W+80=1、W+81=3、W+C=17，并清敌关系对象+1E及全局国别状态为0；选项1→1/1，2→2/2，3→3/4，6→4/3（后者皇帝+2C0减1）。option4收敌总人口×2，option5付50000，资金分别记皇帝+45与收入+4D/支出+71。招降成功W+80=2、W+C=17；割地reason2，藩属/赔款reason3；赔款人口×10。

这些副作用和消息调用交错。若要验证完整成功分支，必须真实创建消息对象，或选择明确止于消息前的片段分别记录；不能把跳过消息调用描述为完整函数验证。原始成功汇编仍见第三轮 `battle_dispatch.asm` 的5F745..5F8EB和5FFED..6035B。
