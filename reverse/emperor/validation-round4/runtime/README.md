## 实测重点

- 割地招降r72和73阈值均1，r74阈值0；r75不进入概率门。r74失败仍推进seed，r75直接失败不推进。
- 称臣招降r99阈值1，r100直接失败。赔款选项无需随机。
- 停战方向非0时贡金/藩属：r110直接成功不推进seed；r111阈值109、r120阈值100，均成功但推进seed；r121阈值99，roll99失败；r199阈值21，roll21失败；r200阈值20，roll20失败。
- 敌方招降先抽割地，失败才抽藩属；r103虽两次抽签但阈值0，最终赔款。r500第一抽必割地。r496/499的[99,99]两骰可最终选择赔款，不能误写为>=496必割地。
- 原特殊标记不是守命令。毒值A5穿过初始化/自动建队不变，证明这两函数没有为它赋默认值；尚不证明整条建战路径从不经别名/块复制写它。
- AI与实际交战确有差异：实际减伤只作用防守方，AI将双方预测都缩放。62905评分写对象内存，不以EAX返回评分。
- 最后属地失败保留当前战斗链节点是实际原分流行为，不是正常删除函数漏跑导致的实验错误；此处不评估场景切换之后是否另行释放。

## 夹具问题与证据审计

首次调试写值使用两位字节，DOSBox调试器会把AF/CF/DF当寄存器/标志名。发现种子207(CF)回读成0及链表指针字节AF改变后，已将probe.py统一改成三位字面量0AF/0CF/0DF。write-roundtrip.json记录全部256字节写入回读完全一致。所有后续实验采用修正格式，清链四位置均重跑通过。

对初轮152个谈判夹具的完整SM协议逐条审计，恰有3条CF种子写入受影响；其余149条无这类字节。3条均在73例seed补测中重跑并核对实际下一seed。negotiation-audited.json只组合149条有效旧证据和3条明确指向新证据的替代记录，未把错误种子结果改成正确观察。

另一个初始断言错误是把[EBP-C]始终当作军力比；停战部分分支会把它复用为概率阈值。已按实际指令改名actual_local_c，并分别检查应为比例还是阈值。negotiation-live-initial-audit.json及第一轮协议保留，含弃用结果，不是最终通过清单。所有最终套件须通过audit_results.py，见audit-summary.json；套件之间有重叠，不把条数相加当成独立覆盖数。

## 补充套件

- flag-persistence-live.json：原保存与加载函数往返，90槽特殊字节在SAV和重新分配的内存一致；checks/flag-persistence.SAV为合成测试战斗，不是原版初值。
- territory-deep-live.json：原因2丢地，核对关系、官员删除、建设队列压缩、劳役扣减、负友好度向零除2、灾害/饥荒等清除和生产乘数复位。

脚本通过common.py复用第三轮probe.py。*-protocol.json含实际请求与响应；checks保存原始内存/存档。运行需要重新确认原游戏对象指针、栈限制和段映射，不可不加检查地对任意DOS进程注入。

- association-live.json：原80D2B→80D59配置关联序号、6670E→66740实际查找。240正确匹配；255匹配到另一名未出战FF官员；256被截为byte0而战斗word256不变，查找结果0。止于查找终点，没有继续执行空指针解引用或声称观察了完整崩溃。
