# 第四轮领土、末属地与链表夹具

本目录为 EMPEROR 原机器码静态路径与 DOS 夹具准备。动态执行由主线独占 debugger 完成，不将本目录汇编片段视作运行证据。所有 R 偏移以完整337字节地区对象为基准（地区0静态 C99AC）。

## 可完整运行的结算函数

`6668F(W)` 包含全部吞并/丢地逻辑，没有战斗界面依赖。调用中的 `6650A` 是自动选择/生成地方文武官，`98A62` 是追加历史事件，`2E73E(...,4)` 是官员按职位排序，都不是 UI。无需跳过这些调用。必备输入：

- 先通过原 `91C87` 加载 KING1，使真实官员链表、31地区关系矩阵 R+B8、全局外交状态 CC1E2 正常。
- 原分配器 `9AC78` 分配 W=0x200、B=0x800，清0，W+5D=B；B 两侧45槽的 type/country 均设 FF，避免0默认值被当作活队。
- 真实官员节点为12字节 `[payload,prev,next]`。遍历 global C992C，payload[0] 是出战关联序号，并非永久官员ID；原KING1中未出战者可全为FF。不能直接复制首两人的默认FF，否则两次匹配同一节点并双重释放。受控夹具须将两个不同真实官员payload[0]设240/241、payload[2]设4，再将 B+6FC/+6FE设240/241；或执行下文原配置块。吞并非属地战只要求6FC存在。
- 若 global CC5F4 在介绍画面中尚未初始化，真实分配0x4E并调用原构造962C8，写该global。0x1C只是本调用最小覆盖，不能用来恢复完整GUI。它是历史对象，字段 +6 胜国、+C首事件、+10当前追加、+14尾事件、+18事件数；此函数不访问虚表。若原对象已存在，则保持原对象，避免遗漏已有历史链。
- 固定 E+E 年龄20，随机种子 C9030=12345；年龄<20的吞并会得到负建筑追加数，而循环只减1并检查低16位是否0，会执行大量迭代，不适合作为正常夹具。
- 对于无生还兵的空槽夹具，初始兵数 B+5F/+61/+63 与 +3C2/+3C4/+3C6设0，避免归队/人口函数意外扣人。

### 吞并

W+80=2，W+81=0 或2；B+12=0（非属地战），B+5D=目标国 f，B+390=0。目标国当前统治0，人口10000；R+13E..141四种职业比率40/20/10/10，R+142动员比5。调用完整6668F，预期：

- E+2E属地数+1，目标 R+2=1、R+4=1、R+BF=1。
- 农/工/商/矿从业人口 R+6/A/E/12=4000/2000/1000/1000，总从业人口R+24=8000；R+22兵员=500，R+1E被置0。
- 目标原敌战状态5清0；目标与30国双向关系全清0。
- 目标文武官职位被配置（自动从可用官中择优，无可用者原函数生成），官员按职务排序；历史事件类型0x16。
- 生产基率每项 `原word基率 + rand()%10 - 5`，实际随机范围[-5,+4]。前轮文字“±5”不精确，应纠正。
- 年龄20时六项建设保持；年龄>20时追加 `T((age-20)*sum(levels)*15/1000)`，按六项顺序轮转+1。

生产率与实际分子会由3B657/3BA99重建，不应仅验证统治标志。

### 丢属地（含最后一个）

W+80=1、81=0或2；B+12=1，B+390=本地l、B+5D=入侵者f；两名真实官员出战关联序号必须不同。令E+2E=2或1，分别检验普通丢地和末属地。

完整6668F预期：E属地数-1；本地R+2/R+4=0，R+BF=0；入侵者对本地关系4，本地对入侵者3；入侵者对中国状态0，本地对中国状态6。地方兵按 `T(本地总人口*本地动员率/100)` 重建，友好度s16向0除2；两名将领payload与各自链表节点都释放。投资队列与本地匹配项先标100、扣E+96该项投入，随后39D26真实压缩15字节队列，空项FF。

末属地额外 E+2E=0、W+11A=1、history+6=f。注意游戏结束 flags/stamina 不在6668F，它们在6564E的后续分支。

本地清除：R+D7 灾害类型、R+D9..DE 六项灾害附属状态、R+11B饥荒、R+124、R+128半年产出累计扣减、R+134阶段计数清0；R+129浮点生产乘数=1.0。清零范围本身不能证明所有附属byte的独立UI名称。

## 战斗链表清理：原片段无 stub 验证

`6564E` 开头销毁真实窗口子对象，介绍画面不具备它们，不能把简单零W送入整个函数。但 `657F3..658AD` 是完整连续的战斗单链表删除逻辑，期间仅调用真实 `9AD58` free 两次：释放 battle payload 与8字节节点。可在真实DOS32上下文设置合法 EBP/ESP，直接执行首条，断点658AD停下；这验证真实机器码分支与真实分配器，不冒充完整6564E UI验收。

夹具：真实malloc创建节点N1/N2/N3、各有独立payload至少0x704；节点 `[payload,next]`，链N1→N2→N3→0；globalCC5E0=head，CC5E8=current，CC5E4会由代码自己初始化；EBP-10是prev scratch。执行前后快照链地址与payload。

| current | 预期 head | 预期 current | 保留链 |
|---|---|---|---|
| N1 | N2 | N2 | N2→N3→0 |
| N2 | N1 | N3 | N1→N3→0 |
| N3 | N1 | 0 | N1→N2→0 |
| 单节点N1 | 0 | 0 | 空 |

插入 9AD58 入口断点记录参数可确认分别free(current.payload)、free(current)，而非读取已free内存来判断。不要将官员节点删除2E8AD误称为战斗删除函数：前者是12字节双链且data由调用者先free；后者是此处8字节单链内联代码。

## 末属地分流与不清链

可把6668F已设置的真实W11A带入 `657E1..657F3`（断在657F3与65902），实际jne会走65902而不进入正常清链。随后原片段 `65902..6591F` 置 E+19 stamina=0、E+F=80、E+10=0。执行前后应核对 CC5E0/CC5E8 与N1数据保持，从而验证末属地路径确实跳过正常删除。此边界不包括6564E前面的UI析构或6591F后场景切换，应明确保留此限制。

## 未知与错误输入边界

- W11A可命名“本次战后触发末属地失败”，不是通用退出标志。
- CC5F4+6保存击败玩家末属地的国家ID，普通战后不会赋该字段；不能从这一写点推断所有历史对象字段的UI名称。
- 普通丢地后仍有下一战且stamina>0会65CCA加载下一战；清链片段不会验证该UI构建。
- 官员链表若6FC/6FE未匹配将解引用0；二者指向同一对象会双重释放。不要用不存在ID来躲避状态逻辑。
- 吞并兵员word与生产乘法dword均可能溢出，尚未覆盖异常修改器值。


## 官员byte0：战斗关联序号的创建路径（修正）

原创建函数2E97B在2EC2E将person[0]置FF。person[1]是官职，person[2]是状态；不可拿默认byte0当唯一ID，也不可拿官职替代B6FC/6FE的关联值。

主动出战原代码4ABD7..4AC28：读取global CCA74所选官员节点，person[2]=4、person[0]=low8(CC5DC)，B+6FC=word(CC5DC)，B+390=30，CC5DC++，B+6FE=FFFF。

属地受袭80D0B..80DA7：先用官职(local+43)查武官，再用(local+13)查文官；分别person[2]=4、person[0]=low8(CC5DC)、B+6FC/6FE=word(CC5DC)、CC5DC++。前面的B+390设置不在此小片段中，应由夹具保留。

若想用原机器码配置而不用SM写person[0]，可分两段执行：80D2B..80D59和80D79..80DA7。每段EBP-1C为待配官员节点、EBP-24为B；global CC5DC=240开始，预期两段后person[0]=240/241、person[2]=4、B6FC/6FE=240/241、CC5DC=242。片段没有UI，除了分配后写入的受控数据，不更改指令。

CC5DC是持久u16全局计数，原加载93D34、保存95B32均传2字节。person只保留低8位，而结算66722/66762将B记录s16与person零扩展byte比较；计数>=256可能无法匹配。此为静态宽度不一致风险，未声称正常流程一定触发。需要追计数是否另有整块清零/重置，不能从仅有直接引用断言永不重置。

## 第四轮原程序动态结果

完整6668F的吞并、最后/非最后属地丢失已执行；原因2丢地还核对关系4/3/0/6、官员40→38、负友好度-5→-2、驻军1000、劳役1000→877、建设队列压缩、灾害/饥荒状态清0和生产乘数1.0。清链四位置记录真实free参数；最后属地保留链表并设置结束状态。详见 [DOS最终审计](../runtime/audit-summary.json)。

`association-live.json`实际执行原关联配置与查找片段：240正常匹配，255与其他未出战FF冲突，256字节截断而word未截断导致查无官员。此处确认了宽度边界，不把受控片段扩展为正常游戏一定会达到该计数，也未继续触发空解引用。先前首两名默认FF的无效夹具已撤回，最终测试均明确建立240/241关联。
