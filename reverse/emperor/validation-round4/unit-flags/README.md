# 单位特殊字节、进守退与独立计谋入口

本目录是第四轮 **EMPEROR 静态证据**。动态结果由 `../runtime/` 的原机器码实验单独记录；下列 DOS 夹具不代表已经运行。所有地址均为重定位后的静态 VA，单位大小18字节。unit+17 是**十进制17，即0x11**，不是0x17。

## 特殊标记：精确作用已定，业务来源仍未定

unit+17（A阵营battle+0x76+slot*18；B阵营battle+0x3DF+slot*18）只有值 **1** 激活系数85；0、2、255都使用100。限定战争代码0x56000..0x69000的直接字段访问共有4处：

|地址|路径|效果|
|---|---|---|
|5967D、596AD|实际交战|行动方1查A单位，行动方2查B单位，特殊值1只把被攻击方的本次损失乘85/100（连同工事一起整数截断）|
|62AB9、62AE6|AI候选评分|同样检查被攻击单位，但代码把双方预测损失都乘85/100；不能把AI预测当实际伤亡|

因此可安全定名为“值1触发特殊减伤的遗留字节”；**没有证据将它命名为防守、计谋、伏兵或地形**。普通“守”命令写的是unit+3，和这个字节不是同一字段。

84210(B)初始化器遍历全部90个槽但没有写unit+17；849FF(B,side,type,N,country)普通自动建队、85942攻击更新也没有写它。手工中央出征编队49E66..49F52逐项填兵种/国别/兵员/装备/训练/防御，同样未写此字节。两个新战斗分配入口49DA4..49E30、80C03..80C6C均分配0x704后调用84210，未看到在调用前对整块清零。观察到的这些路径支持“可能继承堆内容”的解释，但**两个构造函数未初始化不等于完整创建链永不赋值**，仍应以毒值与完整创建链观察区分。直接字面偏移搜索也不能排除经别名或整块复制间接写入。

存档加载935B6在937A6把810字节原样读到battle+65，在93889把810字节原样读到battle+3CE；特殊字节没有转换。磁盘上位置为对应阵营数组首偏移+slot*18+17。三份原始KING1/2/3存档的活动战斗记录均为0，故真实原存档中的单位特殊字节样本数为0，不能声称默认值全0或全1。保存/读档可保留合成战斗的任意该字节值；原函数动态往返仍需独立验证。

## 找到真实部队菜单：“进、守、退”

5A471构造部队命令弹窗，在5A54A以图片编号0x5C载入WINDOW.PIC第92块，循环建立 **3** 个按钮。已解码原位图并目视核实文字：

![原始部队菜单（诊断调色板）](WINDOW-092.png)

图像为横排三列，每列两个竖排汉字：左列“退後”、中列“守備”、右列“進攻”。186CF矩形参数为(x1,y1,x2,y2)：按钮index0对应x64..80、y8..88的右列；index1对应x40..56的中列；index2对应x16..32的左列。初稿将坐标轴和两字标签误读，已按原图与参数顺序订正。5F350..5F53C完整处理三个返回选项：

|返回值|原图标签|实际处理|
|---|---|---|
|0|進攻|W+8B=1，613CA清候选路径，61466计算向前行动|
|1|守備|恢复选择显示，直接将选中B单位unit+3置0x81；未写unit+17|
|2|退後|W+8B=2，613CA清候选路径，61B25计算向后移动|

61B25的后撤范围普通单位2格、type2骑兵3格，受列1..9边界限制，再经棋盘可达性生成路线；不是一项独立远程法术。普通向前/后退路线遇到敌单位仍进入592B9交战动画与59437伤亡结算。6457A的计时分派表依据W+8B执行635B8/63808/63B7A/63951四个路线步进器，1/2对应B方前进/后退，3/4对应A方前进/后退，均走棋盘搬移和接敌交战路径。

这个具体部队菜单已证明只有“进、守、退”；不能把“未找到独立计谋入口”扩大成全程序绝无该功能。object2的Big5字面词“計謀、計策、火攻、埋伏、遠攻、弓兵”零命中，但图像菜单本身说明字符串负搜索并不足以排除功能。现有完整部队菜单、回调及行动计时链未出现第四种独立计谋/远程伤害入口。全局招降/停战另有弹窗和回调；不把它们冒称成其他计谋。

## 补齐unknown_byte_3：本回合行动状态

unit+3（A侧battle+68，B侧battle+3D1）已可用代码行为定名为“行动状态/本轮已行动字节”：

- 5D4CC、5D4FC在轮开始对普通槽清0；
- 59092、590CB在动作结束写0x80；
- 手动守5F4C4以及AI守649AF、649F6写0x81；
- 5EFFA、64BB1、64C85及回合完成检查65BE5、65CA0均以`value>=0x80`跳过，禁止再次选择或纳入未行动候选；
- 0x81可确定为“选择守并已行动”，不能据此说守命令激活15%减伤；真正15%检查unit+17==1。

unit+3其他低位值和显示着色分支仍保留原始值，未把整字节简化成布尔或猜测“防御加成”。

## DOS验证夹具及可判定预测

`../runtime/ai_flag_live.py`只执行原62905，没有UI对象。两个1000人type0队，攻击B1000/A500，防御0，工事0，同槽1；原损失预测76/38。A旗标0、2、255时评分49（76−38+11），A旗标1时评分43（64−32+11）；只改进攻B旗标为1且防守A旗标0时仍49。这也核实函数以W+8C+row*22+x*2输出s16评分，**不是以EAX返回评分**，修正旧报告“返回估算值”的表述。

`../runtime/action_state_live.py`以单个棋盘单位调用原65B57/65C12回合完成谓词，双侧unit+3为0/1/127时应返回AX0，128/129/255应返回AX1，共12个边界预测。

初始化毒值试验应将90个unit+17预置A5，再执行84210和849FF，观察是否保留A5。此试验验证两函数覆盖范围；完整菜单创建、malloc历史、后续设兵与存档往返应另行覆盖。

可重跑 `python3 extract_evidence.py` 生成全部汇编范围、四处直接访问、原始SAV采样计数及原位图。位图使用诊断EGA调色板，文字和按钮位置来自原资源，未声称恢复游戏运行调色板。
