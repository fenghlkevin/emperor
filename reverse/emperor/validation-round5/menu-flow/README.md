# 第五轮原菜单与战场完整路径定位（静态证据）

本目录只提供 EMPEROR 机器码路线及动态验收建议，不声称在此子任务执行 DOS 或点击 UI。地址为原重定位静态 VA，实际 debugger 代码地址需由主线已经核实的 code() 映射换算。

## 正常主循环与读档

**对象修正**：A为global C98D8所指的原主循环101EC栈参数（第五轮动态记录2CAF28）；C为global C9920指向的5字节保存控制器（91C54构造，第五轮记录19D850），两者不是同一个对象。原场景管理器嵌在A+8，场景调度不得以C+8替代。第四轮直接load/save使用C仍正确。

应用入口循环15841在15A67调用101EC(A)。101EC不是每帧返回的函数：11782跳回10202，永久处理事件；10233调用1BF44(CCD74)读事件。新启动在10202设置断点，可记录合法游戏CPU寄存器与原ESP/EBP，然后恢复该原上下文而非手工构造主循环栈。

读档对话框2BBCE匹配this+A+i*4五个按钮，this+26非0时在2BC2C调用2BD6F(this,slot)。原wrapper2BD6F先将全局保存控制器C.word0设1，然后91C87(C,slot)。原主循环处理后续场景和读档恢复。单独调用91C87不能证明UI读档全流程。

## 主动出兵菜单构造

战争管理窗口构造器495EE，虚表C2134的+2C回调为4967E。49164是管理窗口创建的选将等下属对话框，而非整个战争菜单构造器。

完整4967E中的创建路线：

- source==this+1C进入49D76；首次this+34==0时49D92分配8字节战斗链节点，49DA4分配0x704战斗数据，49DD2调用84210。
- this+30保存节点，this+34保存battle，node.payload=battle；目标国家this+44写battle+5D，本地标记battle+12置0。
- 菜单添加单位与将领，4ABD7..4AC28分配持久出战关联序号。
- 4AD32..4AD8D把节点完整追加到CC5E0链尾，原84457完成战斗初始化。该路径适合特殊字节来源观察：在9AC78返回B后毒化，再让原callback从49DAE连续执行到4ADC6，观察各阶段写入；这种调试辅助输入必须在动态报告明确披露。

## 场景23与战斗开始

原场景管理器3D82A(S,scene)，S=A+8；scene=23时跳表3DE88[23]=3DE1B，分配0x11E，3DE49调用5C1B6(W)，结果存S+3C（也即A+44）。主循环112DB读取CCA7E[CCA92]，非0时11320走此正式构造。

5C1B6先初始化父窗口和大量真实子对象字段，再5C2BA调用65CCA设置CC5E8.payload为W+5D、构造消息框、初始化本战场景。它并未立即创建6564E无条件析构的W+3B和W+43。

点击“开战/布阵确认”相应source为W+20，原5CD22在5CD72确认来源，调用58350构造W+3B、5A76C构造W+43，再创建其余战斗UI。完整UI验收必须经过此分支，不可以零W或假虚表送入6564E。

## 结束消息与完整战后退出

W+8消息框回调经W+C跳表5DD14：状态15、17均走5DCA9，经真实消息框关闭调用5DCD1→6564E(W)。状态13/14走5DC28（继续/切下一场战斗），不能误当结算入口。

完整6564E流程：战斗场次计数增加、恢复图像、析构真实战斗子窗口→6441B清场→W+80非0时6668F完整结算→W+11A判断最后属地→正常清除当前battle和8字节节点（分别原free）→扣体力50→有下一战且体力非0时65CCA加载→无下一战或体力耗尽时68031(W,7)并2DDAC/2D806/7E613返回上层。

末属地分支65902设置E+19=0、E+F=80、E+10=0，跳过正常清链。必须继续执行6591F后场景返回代码，才能把第四轮片段验证提升为完整战后退出验证。

## 动态判定边界

建议保存菜单创建前、真实malloc返回、初始化器后、全部菜单确认后、进入战场、开战确认后、结束消息确认后、返回主界面八阶段的CPU与内存快照，并在完整原UI运行中记录9AD58参数。仅调用原回调属于原事件链验证，只有鼠标/键盘真实驱动并取得画面才能称菜单全流程UI验证。

完整原主循环对象无需重建，应重启测试DOS实例或恢复事先记录的合法10202上下文。不要把介绍画面中任意DOS内核中断断点的CS/SS手工改成游戏段再跳入函数。


## 完整菜单回调失败诊断补充

4967E(this, source, result)确为三栈参数ABI。41BF4只返回FF，41BD8只返回0；W虚表+30=3E245关闭已有W+8消息框，selector虚表+30=865A7关闭其+6真实窗口。代码未显示首选0需要额外第四参数。

但首选0在497AD调用2DEC8(CC5A0,7)：先找官职7并标状态2，然后2DDAC重建官员名单，2D806对CC5A0内原图像指针绘图。CC5A0在11895的场景11分支构造（11D3A分配0x1F5、11D68调用2C838、11D96写global）。因此从介绍/其他SAV场景直接3D82A(S,7)并不足以证明战争菜单先决UI有效，须先核实CC5A0是真实活对象，必要时经原会见官员场景初始化。

保存控制器C.word0为待恢复flag，C.word2为加载的目标场景。101EC在10432检查flag==1，10573复制C.word2→A.word2，然后105A6完整调用11895(A)恢复场景。这与A当前场景0/11、3D82A的下属战争scene7是三层不同状态。

主线调试日志debug-callback-protocol的1F319E映射原2307B图像复制函数；任意BREAK停在DOS内核不能单独证明已经退出COMMAND。该日志selector地址在执行后为FFFFFFFF，须在调用前核查虚表，并用497A0/497B2/497CC/497CF/497F1/497F4/49806连续断点定位最早异常，不能据执行后内存直接猜测构造时虚表损坏。以上为诊断候选，不冒充已证实根因。
