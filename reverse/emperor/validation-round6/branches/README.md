# 255/256 在其他原结算分支的风险地图

本目录只包含静态核对和未运行夹具草案；未访问共享 DOS 桥。原 6668F 完整汇编见 settlement.asm，动态已有结果须引用 round4/round5，不将本轮脚本当作证据。

## 结算选择与实效边界

W+80=2 为玩家胜方，其他值进入失败侧。W+81 原 switch 表实际 5 项为：

|W+81|胜方表 67280|失败表 67718|官员实效|
|---|---|---|---|
|0|668BF|672E4|胜方吞并并恢复官员；失败删除出战官员，属地战同时丢地|
|1|6725E|67712|667AF 已恢复官员状态，不吞并/不删除|
|2|668BF|672E4|与0同样进入吞并/删除，不等于一概和平结束|
|3|6725E|67712|667AF 已恢复官员状态，不吞并/不删除|
|4|6725E|67712|667AF 已恢复官员状态，不吞并/不删除|

表是读取 relocated.bin 对应 little-endian dword 的结果；线性汇编将表和后续跳转分派误解为指令，不可据此给 reason 数字凭空换名。reason1/3/4 的上层 UI 含义复用已有战场分析；本轮重点区分删除与恢复。

- **非属地失败也删除一名官员**：67321 取第一查找节点，67324 取其 payload，67326 调原 free(9AD58)，67338 调官员节点删除2E8AD。这比 round5 非属地 reason1 的状态写风险更重，不能用已返回的 reason1 推断 defeat 安全。
- **吞并**：668BF 先加属地数、目标统治/归属/R+BF 置1，再在66921（非属地）或6693F/66960（属地）恢复将领。255 错配时仍可能继续完成吞并；256 空节点时，目标所有权已经变更后才触发低内存读写。是否完整返回尚须逐例执行，尤其后续自动选官6650A会受未释放真实将领状态4影响。
- **属地丢失**：67345 起先扣属地数及最后属地标记，再设置4/3外交关系、统治/R+BF清零，674AD 起删除第一官员，674CC 起删除第二官员。异常可能留下已经丢地、已经删除第一官员、但尚未清投资/灾害/历史的部分结算。
- **普通恢复**：667C0 非属地读节点；667DE 和667FF 属地读两节点，均随后写payload+2。第二关联错误并不阻止第一状态先恢复。

查找只比较 s16(B+6FC/6FE) 与 zero-extended u8(person+0)，不查官职或状态。255并非每次必错：实际出战节点如果位于任何其他FF/历史255之前则正确；草案特意选择链首FF作无关见证、后续真实官员作将领，以复现正常默认值碰撞。256及之后到65535均无法匹配合法byte。

## 同一属地战两次分配

|创建前计数|B关联序号|第一查找|第二查找|典型受控影响|
|---|---|---|---|---|
|254|254/255|真实武官|链首FF可能错配|恢复/胜利错恢复无关官；失败删除武官及无关官，真文官仍4|
|255|255/256|链首FF可能错配|0|恢复/胜利先改无关官后写低内存；失败先删无关官，再将低内存dword送free|
|256|256/257|0|0|第一次恢复/free已经使用低内存，两真实将领仍4；后续取决于实际DOS映射与allocator|

单场从255开始分配255/256尤其重要，不能只验证分别非属地255和256。这里不会把空指针推断为必然立即 DOS/4GW 异常。round5实测 reason1 256读取线性0得到0xF000CA60并向0xF000CA62写0后原函数返回，仅建立该恢复分支的观察；free(0xF000CA60)和delete_node(0)需要新实测。

## 最小验证夹具与审计

fixture_draft.py 已 py_compile，但未运行，无 import-time RPC。调用者注入自己独占的 probe 模块，先正常载入原存档及暂停真实32位上下文，再 build(p,case)、完整 settle(p,fixture)。草案以原 malloc 创建零W/B；45槽双方type/country=FF，兵数0；年龄20，地方拥有状态1；原80D2B..80D59、80D79..80DA7写将领关联并累计计数。选择链上两个不同真实官员，保留链首FF见证。W/B是受控结算对象，不冒称实际战场创建。

建议执行顺序：非属地 reason1 255/256 对照→吞并255→失败255→local254/255→local255/256→256删除分支。每个破坏性用例独立新DOS进程或原生完整状态检查点；重新91C87读档不能恢复未知线性写或损坏allocator，不能用单进程读档反复试free(null-derived)。同时核对以下证据：

1. 查找结束节点 [EBP-10]/[EBP-1C]、低内存0 dword、两真实将领byte0/state，以及完整官员链节点地址列表。
2. 入口9AD58的ESP+4 payload参数；入口2E8AD的ESP+4为&C9928，ESP+8为节点。断点记录具体调用返回地址可区别官员free和战斗清链。
3. 67324/674B0/674CF危险读取前后EAX及传入free参数；不替换或跳过原free。delete_node若收到0也要追真实原函数。
4. 返回/ DOS异常/超时分别记载，异常场景记录 PC、寄存器、领土和官员链的已经完成变化。判定官员被删除须靠链不再包含该节点及真实free参数，不读取已释放payload来判断。
5. W+11A最后属地标记以及完整6564E退出需真实GUI对象另测，本草案不把6668F返回等同战后退出。

已知草案限制：受控使用前两关联配置块代替真实菜单或自动受袭函数；所有兵队空，因此只隔离将领/领土/历史而不验证伤亡归队；未覆盖reason2与0的上层生成差别；未进行自然累计257次实机游戏。

官员节点删除2E8AD也**无null检查**（official-delete.asm）：入口2E8C6先读node+8；node0且低内存+8非0时进入中间节点分支，经2E8F7/2E8FD读取低内存+4/+8，再在2E900/2E90F向由两者组成的指针写next/prev；低内存+8为0时2E917读取+4，经2E91D改全局尾，再2E926向derived_prev+8写0。随后原free(node)只释放节点，payload由上层先free。因此即使 allocator free(null-derived payload)返回，下一步也不是安全free(0)，仍会进行低内存-derived链写。
