版本：0.1，整理日期：2026-10-15。目标：让开发者据此拆分模块、建立数据模型、实现已恢复规则并编写验收测试。依据是用户提供版本的程序、存档、资源及六轮分析，不是原作者设计书或源码。

**主行为基线为 EMPEROR；KING/QUICK用于交叉核对。本文定义了可以开工的复刻规格，不代表全部原版功能已被证明恢复。** 未证实的字段、操作和边界有明确阻塞项，不以常识补齐。原版地址用于追溯，不能直接成为新程序对象ID或数组下标。

## 必须理解的证据分级

- **D：DOS实测**：真实DOSBox-X/DOS4GW中执行原代码，有输入、输出/字节快照或协议。多数是受控原函数/控件事件，并不等同自然鼠标游玩。
- **S：静态确认**：已定位原指令、字段/调用和顺序，未覆盖全部运行情境。
- **I：推断**：结构/用途有间接依据，尚不能承诺兼容。
- **N：新实现约定**：为了实现和工程安全设计的接口、ID、事务、事件与模式，不能冒称原版行为。

每个模块采用明确命令，返回字段差异、账目、事件与随机轨迹。公式中的 `T` 是有符号向零截断；禁止直接用Python负数地板除法。16/32位截断时机、数组遍历顺序和seed消费顺序也是行为的一部分。

## 兼容承诺和实际完成边界

1. 可先完成“现有旧档导入 + 已确认经营循环 + 外交 + 核心战斗/结算”的功能复刻。缺口见第09章，不能把尚未证实的独立计谋、所有药效、所有特殊事件当作已具备规格。
2. 固定新实现模式 `modern` 和历史回放模式 `legacy`。每个新档记录模式及规则版本，不允许运行中静默切换算法。
3. `legacy`是有证据的逻辑兼容；不复现任意DOS未初始化堆值、低内存写或宿主崩溃。遇此类状态返回明确诊断，保留原始输入。
4. 最新主流程证据：第六轮已经从实际控件出征，经原时钟/宫廷事件、队列调度进入真实战场构造；**该次战后退出仍未端到端通过**。七组额外战后分支是完整6668F受控执行，不替代端到端结论。
5. 正常累计到255/256的规则和限制已追踪，尚未无修改自然游玩257次。修复模式的长期稳定性须新实现自己验收。

## 证据优先级

同一字段按“具体实测输入输出 > 已核对的原指令 > 既有解释文本 > 攻略/修改器标签”判断。后轮报告只在它实际覆盖的条目上修正前轮；不得用“轮次更新”笼统替代证据。尤其：完整地区R与数据起点R+2不可混用，磁盘记录也不是内存结构dump。

文档内相对链接指向同目录原始资料，字段和验收数据可用 `python3 reverse/emperor/replica-design/build_catalog.py` 重建；用 `python3 reverse/emperor/replica-design/validate.py` 检查引用、数据来源和数值用例。
