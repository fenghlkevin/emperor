# 国库记账与旬流水

财政记账实施于2026-10-16；产业开发、职业转换、建筑收益与粮食救济当前已由各业务模块接入。数据层级见[数据字典](data-dictionary.md)，完整兼容范围见[存档版本兼容](save-compatibility.md)，结算时点见[旬结算顺序](turn-settlement.md)。

## 余额与流水

国家 `fiscal.treasury` 是唯一国库余额，顶栏副本在保存前由校验结果同步。`finance.mjs` 的 `postTreasury` 统一登记国库现金收付，`transferTreasury` 同时登记两个国家的转账。

已接入：常规税收和预算支出、户部五项政令、施工、科举、封爵、司法调查、地方委任、征兵、祭祀、通商、贡银、战利银和国库祥瑞。新国家建立时的初始余额作为期初，不伪装成财政收入。地方现金、粮食、军备和人口仍由原业务模块处理；此版本统一的是国库现金流水。

旬流水满足：

`期末国库 = 期初国库 + 实际收入 − 实际支出`

`期末债务 = 期初债务 + 新增应付未付`

预算预测与实际收付分开。现金不足的既有强制付款仍按原规则增加债务，但实际支出只记已付金额。例如10两现金应付30两，实际支出10，新增债务20，期末国库0。新增消费规则、利息和自动还债均未引入。

分类为常规财政、政令与事件、转账与履约。中央补助和强征是国内资金转移，国库收付不等于全国新增财富。报表保留现有预算预测，并增加实际旬账、分类、余额核对及最新一期最近20笔明细。

## 账期与重复处理

首笔现金交易或旬结算建立该旬期初余额。当前旬实时累计，进入后续旬后不再回写已封存账期；如果没有现金交易，不创建空旬账。最多保留36条旬汇总，每旬保留100笔详细交易，更早明细计入结转汇总，完整收入、支出、债务变化与期初期末仍保留。每旬保留交易键以阻止已裁剪明细的重复提交，存档上限为4096笔/旬。

常规财政是否结算，以独立的 `accounting.lastSettledTurn` 判断，不以“是否已有本旬流水”判断。这样，司法调查或祥瑞先入账，也不会导致常规财政被跳过。

政令沿用各业务命令序号；自动结算沿用原有旬标识，并对现金交易增加唯一键。重复打开喜报仅确认已读，不发放奖励。国家间转账在私有副本验证双方后一次发布，失败时双方都不变。

## 保存失败与旧档

`persistence.mjs` 统一执行：检查候选状态版本、复制候选、扣行动成本并处理必要的耗尽结算、校验完整存档、写入本地存储、成功后发布状态。保存失败不发布内存状态，不扣体力、不推进回合，也不推进政令编号。失败候选可以重试；已经提交的对象及基于旧版本生成的候选会被拒绝。

存档使用 `saveRevision`，兼容范围内缺此字段的档案从0开始。财政结构在现有存档中使用独立 `accounting.version=1`；不依靠更改全局版本清空进度。没有财政记账字段的旧档以实际余额为基线，原账标记“旧版常规收支”，不根据不完整旧账修改银两或债务。同旬首次新交易会把原账保存在该旬 `legacyBaseline`，避免出现两个相同旬序的记录。再次读取不会补发、重扣或重复迁移。

导入大小上限调整为8 MiB，以容纳新增的36旬财政明细；仍校验完整存档和流水恒等式。本地存储容量不足时，操作失败并保留原进度，可导出原有状态备份。

## 验证

- `npm test`：包含财政专用测试及既有业务回归。
- `npm run test:finance`：Electron真实表单的写入失败、重试、重复点击、存读档、实际流水显示、喜报确认失败及耗尽结算回滚。
- `npm run test:revenue`：原户部普查、军备采购、补助、税率、强征及存档重载回归。

财政新增测试使用固定创建时间或显式奖励序列，避免“没有考虑随机奖励”的断言时好时坏。另验证随机事件与常规财政共同发生时余额仍对账。现有内联样式CSP提示未在本次修改；桌面测试单独计数该已知样式提示，其他错误仍使测试失败。

历史阶段验收（2026-10-16）：当时180项单元测试全部通过；财政专项桌面验收、原户部五项操作桌面回归均通过。桌面专项包含模拟本地存储写入失败，未修改用户日常存档目录。

## 平衡规则1（2026-10-17）

本国新局中央其他收入400两/旬。新增繁荣公共服务费，按`round(Σ各州 人口×0.0013×max(0,生活−50)/100)`计入行政支出；预算和实际常规结算共用同一口径。商业营业增益除以600、封顶10%。粮食在灾后期初先扣超安全库存8%的陈粮损耗，再计当旬生产与口粮；详见[粮食救济](food-relief.md)。旧档既有钱粮和其他收入不重置。
