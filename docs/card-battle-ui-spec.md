# 军阵卡牌 UI 与动效验收设计

日期：2026-10-22。参照本会话最初认可的[UI原型](screenshots/card-battle-original-prototype.png)。在 `codex/card-battle` 独立工作树实现。

## 布局与视觉对应

- 沙场与城关：沿用既有金色落日沙场插画，中央留空承载交锋，上下由雕木、旗帜和古铜色边框围合。
- 左上战役牌匾：深木底、古金边、宋楷标题；敌方背面手牌位于上方偏左，不覆盖敌将。
- 上下主将：本人肖像居中，圆形金属相框；右侧竖旗显示姓名与生命，敌朱红、我方青玉。使用真实人物ID和既有资源，不沿用概念图示例孙刘曹。
- 场上战斗卡：5:7竖向长方形、大幅立绘铺到卡底，顶部窄名称条，底角攻命；不沿用手牌的费用珠、技能纸面和文字条。友方用青绿细边，敌方古铜边，完整技能可悬停查看。
- 中央上下两行：按已确认的炉石规则各七个部队位，卡片固定比例、均匀间距；空位低对比图腾。人数进入军情，卡面突出费用、攻、命，不与实际兵员混用。
- 左侧回合盘：圆形古铜牌，显示回合和行动方；右侧青玉宝石“结束回合”按钮，下方撤军。
- 底部：完整手牌与战斗卡分别排版；连续浅扇形手牌位于雕木桌面；费用左上蓝色圆珠；普通无技能部队的立绘延伸到卡底，攻命置于底角；有技能的部队和人物保留说明纸面，攻命置于插画与说明的交界，攻击古铜、生命朱红。计策保留说明，无攻命。右下青玉军令珠，花费后熄灭。
- 人物卡按本人肖像、朝代与文武定位展示，独立的专属技能标题；兵种卡沿用对应兵种插画。两者使用同一卡框体系。
- 鼠标悬停放大完整卡片并显示技能和来源；点选需要目标的卡片后，高亮合法目标，右键或Escape取消；零军令也可以攻击。
- 卡录提供全部100个人物定义的只读检索；能查看不代表已取得或可参战。取得、任命及真实兵源要求由引擎判断。

## 动效时序

| 行为 | 动效 | 预期时长 |
|---|---|---|
| 抽牌 | 从本方牌库沿弧线滑入手牌，费用珠渐亮 | 280～360毫秒 |
| 出部队／人物 | 手牌抬起并飞到空位，渐变为战斗卡，落定时尘光和边光扩散 | 飞入620毫秒，落定光尘880毫秒 |
| 攻击 | 蓄势、带轨迹冲刺、双刀光与冲击圈、命中停顿、返回 | 蓄势300＋冲刺500＋停顿220＋回位500毫秒；伤害数字1100毫秒 |
| 主将技／计策 | 完整技能卡与说明先保持可读，效果飞抵目标才更新生命与命中反馈 | 亮牌350＋阅读1900毫秒（主将技蓄势1900）；飞行380～470，命中880毫秒 |
| 受伤／退场 | 命中时扣血并浮起伤害数字；反击数字跟随攻击卡；死亡命中前保留，命中后归零淡出 | 数字1100／受击520／退场700毫秒 |
| 护甲盾 | 金色护罩碎光，阻挡伤害时无生命扣减 | 260毫秒 |
| 治疗／强化 | 青玉光晕，显示恢复／提升数值 | 320毫秒 |
| 换回合 | 青玉结束按钮蓄光扩散，随后出现换回合提示 | 点击440＋提示950毫秒；就绪玉光3秒／流光4.5秒循环 |
| 胜负 | 暗场、金印／朱印，保留最后场面后进入结算 | 600毫秒 |

合法动作先完整提交存档，画面临时保留命中前的主将生命、护甲、场上卡牌与攻命，待攻击或技能实际命中才更新数值和退场；动画期间锁定战斗动作，关闭重开从已提交状态继续，不重复造成伤害。支持正常／快速动效和系统减少动态效果；自动战斗加速但保持动作顺序。动画不能改变胜负或抽牌随机状态。

## 实机验收

在1440×1000、1280×800和紧凑窗口检查：布局不溢出，七个部队位、完整手牌、主将与费用均可读；本人肖像加载；真实鼠标出牌、目标选择、零费用攻击、护卫／突袭限制；动画顺序、双击防重入、动画中保存离场、JSON续战；完整对局与真实来源伤亡结算。保留与原型同视角的最终截图及界面差异记录。

2026-10-22 视觉复核修订：按用户重申的原图重做，场景使用原型参考提取的物理底板；卡片区分场上与手牌两种完整布局；计策使用12幅独立叙事插画，移除大字印章替代画面的处理。费用与攻命徽章缩小，手牌由交错倾斜改为连续浅扇形。原型对照保留部队在场上与手牌中的实机卡面截图。

卡框使用可随目标长宽伸展的铜饰边缘，避免场上5:7竖向长方形牌面出现浅色留白边带。普通部队手牌不创建空技能栏；人物及带技能部队的攻命徽章不遮挡说明。

最终按用户反馈取消桌面倾斜：场上卡框正置，5:7矩形保持固定。上场后仅立绘轻呼吸（8秒）、衣甲流光（9秒）、微粒（7秒）和细边光（5秒）循环；名称、攻命、卡框和点击位置稳定。减少动态效果时停止这些循环。十张手牌在三种窗口下通过重叠适配保持矩形，不拉窄卡片。

[实机动画录屏](screenshots/card-battle-v3-skills.webm)覆盖持续待机、登场、火攻、箭雨、强化、治疗和主将技；18项动效检查包含16种技能、登场以及待机状态不变验证。

## 截图／录像反馈修复

- 主力／精锐是不同预设费用档的名称：编牌先扣除前锋、小队、人物牌，剩余部队卡按两张主力、一张精锐的顺序加入；并非训练度达到阈值后自动升级。训练单独修正属性。UI展示仍沿用开战快照的原名称。
- 插画图集按原始格子的 viewBox 等比裁切，使用 `xMidYMid slice`，不再把正方形格子强行拉伸为竖长矩形；主将和区域人物也保持比例。
- 手牌按钮的命中框保持固定，内部牌面负责扇形、抬起和放大；抬起的牌面也可以点击。移除与详情面板重复的卡牌原生提示；详情放在牌面旁边。手牌高于主将和状态条，状态文字改在左侧空区，不横穿手牌。
- 主将技能采用独立图形图标、名称和圆形费用区，三者留有间距。
- 正常速度下完整技能牌飞入350毫秒，静止展示1900毫秒，再播放飞行与命中；名称与完整效果说明栏持续显示约3.3秒。快速模式保留相应加速，减少动态效果仍直接提交结果。
- 新增13项定点鼠标回归：1440、1280、1000窗口下，指针停在原卡片下沿不产生反复进入／离开；检查标题、说明面板和状态条不遮挡当前卡，技能图标／名称／费用不重叠。

## 攻击节奏与牌组构成修订

双方普通攻击使用同一时序，正常手动速度中不会额外加速敌方动作。冲击圈和双刀光持续880毫秒，伤害数字1100毫秒；攻击回位后才恢复操作。致命目标不提前移除。主将、部队、护甲以及计策／主将技统一按命中时点刷新数值。保存离场仍从已提交的真实状态续战，不重复攻击。

结束回合按钮内部增加玉光呼吸、光带流动与点击扩散，按钮和原型铜框位置固定。系统“减少动态效果”关闭循环和过渡，游戏计算保持一致。

原默认仅100名子队士兵，30张牌会包含4张部队／人物和26张计策。两处出征入口现在默认按真实兵装和在任将领拟编最多450名子队士兵＋亲卫，在可用兵种间分配，库存足够时是18张部队／人物＋12张计策。自动按库存全量布阵按钮仍可使用；玩家仍可改人数。出征编辑、核阅以及战斗右下牌库均展示构成。库存或可用将领不足时按实际生成，不虚构兵员或人物。

抽牌仍严格随机洗牌、逐张抽取，不能保证任意时刻手牌包含三类牌。人物只有实际率队参战才入牌。已有战斗保留开战卡表和牌库，默认布阵调整用于新开战斗。[抽牌审计](card-battle-draw-audit.json)检查1000组种子、52000次抽牌／爆牌，无偏离已洗牌顺序；正常牌组也出现连续计策。

新增[攻击节奏实机录屏](screenshots/card-battle-v3-attacks.webm)与[11项逐阶段验收](card-battle-motion-validation.json)，覆盖敌我攻击主将／部队、致命退场、减少动态效果和两处出征预览。录屏中的5攻10命等是明确的动效测试属性，正式基础属性以卡表为准。

## 施法后的持续状态与结束按钮文字

卡面在名称下方保留当前生效的短标签：临时攻击显示“攻+3 · 本回合”，持续攻击／生命上限修正分别显示“攻+2”“命+2”；冻结、沉默和未消耗的护甲盾均有明确文字。超过三项时压缩为两项和“另N项”，悬停详情完整列出全部效果。强化攻击与强化生命上限采用青绿色数字，受伤生命仍保留受伤色；降低攻击为红色。冻结具有冰蓝内边框，沉默降低插画饱和度。

详情增加“当前生效”，列出效果、解除条件与属性拆分。例如基础1攻的前锋接受奋勇进击后显示“攻击 1（基础）+3（本回合）=4”，回合结束同时恢复1攻并移除临时标记。持续标签从实际存档字段推导，读档仍然保留，效果移除或护甲盾被消耗时不留过期标签。治疗、直接伤害等即时效果只显示命中数字，不伪装成持续增益。

命中时在受影响卡牌附近保持1700毫秒的具体说明，例如“攻击+2 · 生命上限+2”“已冻结 · 无法攻击”；不再把攻击与生命两种数值相加成一个含糊的“+4”。持续标记与数字在命中时同步刷新。卡片名称、底角数值、卡框和点击区域不变。

结束回合按钮文字缩小到1.65cqw（14～28px），限制在玉石按钮70%宽度内居中；1440、1280、1000三种窗口检查文字墨迹与圆框留有足够边距。
