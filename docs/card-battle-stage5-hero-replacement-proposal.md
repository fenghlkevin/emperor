# 阶段五可选英雄替换：身份、亲卫与技能兼容方案

2026-10-23。状态：**方案已交付，玩法未实现、未启用、未获具体实施授权**。仅面向未来新开局，不设计旧存档兼容、迁移或保存恢复。音效继续暂缓。本文件不修改规则6、卡表、AI、30张牌组成或正式战斗行为，不把设计审阅写成未来玩法验收。

## 结论与边界

可实施方向是“临阵更换指挥人物，原亲卫和实物军阵保持原来源”，不是改写开战军令或把另一个物理兵员单位强行设为主将。当前主将人物与亲卫绑在一起；若未来实施，需要先增加指挥角色层，把“开战亲卫／原领队的不可变快照”与“此刻实际指挥的人物”分开。

第一版候选范围限制为**与原亲卫同一实际驻地、本场已参战的己方非主将单位领队**。候选单位开战时须有真实士兵，候选人物须在现有cardPeople中有固定ID；不能从牌册随意召来未参战历史人物，也不能临时随机重抽人物。守城中央、地方、盟军分别只能在该实际来源内提名；若任意一方没有合格候选，则该配置不允许开战，不用凭空人物或不对称自动补牌兜底。

候选方案暂名“临阵易帅”：最多1张，占普通计策名额，保持整副30张。试验起点建议5军令、每方每场最多一次，仅更换指挥人物与其实际能力对应的三类现有主将技，不附加治疗、护甲、抽牌、登场／遗计或临时攻命。5费只是未来验证用设计参数，尚未进入正式卡表，不能视为已平衡。具体人物、费用与是否实施须在用户另行授权后确定；当前继续阶段六，不为可选牌等待决定。

## 已核对的现有约束

| 当前实现 | 为什么不能直接热换 |
|---|---|
| `card-battle.mjs`的leader按side与unit.commander定位 | 改commander标志会同时改变兵员记账、卡库、预备兵和主将来源 |
| ensureCardPeople／validateCardPeople按官员ID与固定人物快照关联 | 换名称或cardPersonId不能代表真实人物调任，会破坏来源一致性 |
| attachCards排除原主将人物进入部署人物卡 | 新指挥者也须预先排除，否则同一个人同时出现在主将和部署人物卡 |
| 真实亲卫阵亡=`ceil(initial×min(30,heroDamage)/60)` | 重置伤害或把损伤套到另一支亲卫会抹掉既有阵亡／重复损耗 |
| 武器allocation和supplies固定原主将驻地 | 更换人物不能把已占用装备改记到新驻地或再占装一次 |
| 奥秘、地标保存原unit／source／person来源 | 旧军令／设施不能随头像换人而改作者；揭示仍须保密且因果可追溯 |
| 出征与守城按开战军令重建编队／人物／训练 | 直接改general、commander、source会被正式校验器拒绝 |
| 主将UI、技能日志、公开历史、战果目前读取原亲卫领队 | 只换头像会使技能、历史和实际人物不一致，须一起支持角色快照 |

当前约束审计见 [结构审计](card-battle-stage5-hero-replacement-audit.json)：6种直接改写均被正式校验器拒绝；其反击样例由实际武器攻击造成主将27命、累计3伤害、真实亲卫阵亡5人。该审计只证明现有保护有效，不证明新角色层已经可运行。

## 拟议数据结构：保留不可变来源，显式记录当前角色

以下字段仅为方案命名，尚未加入类型或运行时。

- `command.heroReplacementSelection`：开战前唯一候选的实际unitId、personId、sourceId、定义ID及能力快照摘要；随军令核阅，不产生新单位或人员。
- `players[side].leaderRole`：`originEscortUnitId`、`originPersonId`、`activePersonId`、`candidateUnitId`、`candidatePersonId`、`replaced`、`changedAtPly`。初始active等于origin；只允许一次从origin切至锁定candidate。
- 原`units[].commander`、general、cardPersonId、sourceId、initial、training、bonus与开战亲卫保持不变。它们代表原始兵籍与军阵来源，不当作此刻人物所在角色。
- 新统一访问器`activeLeaderPerson(b,side)`供主将姓名、肖像、能力、施技者及当前角色使用；原leader仍供亲卫伤亡、实物来源和初始军令使用。不得全局替换所有leader调用。
- 候选人物从开战人物卡生成池排除，其所辖士兵仍按原军籍生成普通部队卡和预备兵；不消失、不再配一份人物卡，也不补发别的人物。总兵员、人物唯一次数与30张组成重新校验。任意手牌、牌库、战场、弃牌中的部署人物实例均不得与候选／当前主将重复。

候选提名只移动人物的**战场指挥角色**，不是把候选单位士兵并入亲卫。换帅前要求候选来源单位仍有生还兵员、未撤离且人物尚未占据其他活动角色；换帅后该人物明确转入原亲卫指挥位置。其原单位继续按原始快照记账，后来该单位士兵耗尽不反向复制或杀死已经转移角色的人物。原主将转为非活动指挥角色，不获得另一张部署牌、不重新入场、不写真实官职升降。战果分别保留“原领队”“指挥更替记录”，不能把历史原领队改写为新主将。

## 一个原子动作的拟议顺序

1. 验证正式己方play回合、尚未结束、当前主将生命大于0、替换未发生，卡仍在手且费用足够；候选ID、驻地、能力、存活来源与开战提名完全一致，无人物重复。
2. 完成全部校验后一次性扣军令、移手牌入已用区，并设置角色变更；非法目标、取消、费用不足或失效候选均不得部分扣费、改身份或写记录。候选来源在抽到前已败退的卡保持失效且仍占原有牌库名额，不强制替换或重抽。
3. 从候选锁定的真实能力调用原commanderSkill，更新当前技能；不套人物卡的登场／遗计，不重算已有部队攻命、训练、军籍或开战加成。
4. 原样保留当前hero、armor、累计heroDamage、fatigue、mana上限／剩余、ownTurn、discount、powerUsed、heroAttackUsed。技能是否已用属于该方本回合而不是人物；更换技能不能再用一次，更换人物也不能多攻击一次。
5. 已有武器ID、攻击、耐久及实物账本原样保留；更换人物不是换装、不耗耐久、不返装、不加装。随后真正攻击照旧受护卫、潜行、护甲、奥秘及同时反击约束。
6. 己方／敌方奥秘顺序、匿名封签与旧来源不变；活动地标的原作者、剩余次数、冷却与同一七格不变；替换不算攻击，不触发攻击奥秘，不触发部队死亡或腾出兵员场位。
7. 一次记录公开旧／新人物ID、中文名字及原亲卫来源、费用和不变的生命／护甲／行动次数；数值和肖像在换帅接触时点一起揭示。后续技能事件用新人物，过往事件仍用当时人物快照。
8. 继续正式结束／清理链。若前一效果已致命，战斗已结束，不能插入替换逃避失败或复活亲卫；不存在“先死后换帅”的特殊窗口。

例：当前27命、2甲、累计亲卫伤害3、武器1耐，技能和攻击都已使用。支付拟议5费换帅后仍27命／2甲／累计3伤害／1耐；亲卫阵亡仍5人（本例initial100），本回合仍不能再施技或攻击。接下来治疗只改变生命，仍不抹去这5人阵亡。此例是方案规则，不是已实现演示。

## 与现有身份和账本的兼容

**真实人物。** 历史人物仅按personId／历史定义关联；随机人物使用已经按能力专有池生成的固定身份和肖像。选候选、查看、抽牌、换帅或重播均不能重抽、改名或把名字当ID。提名须在开战人物卡分配前完成；候选被排除后，普通部队仍占用同一unit的原兵员，不能因“人物没有部署卡”增加士兵。

**亲卫与伤亡。** 全场只存在一份原亲卫兵籍，heroDamage始终累计在它上面，双方任何治疗或角色变更均不得下调其死伤峰值。原主将离任不触发撤军、死亡、兵装核销或开战补给。最终各unit与原驻地的士兵／九兵种损耗按已有一次结算执行。

**武器。** 实物所有权仍归原军阵，不随人物迁库；来源和lost原因保持不可变，仅真正耗尽、换装或主将最终失败沿原规则核销。候选同源约束防止把地方／盟军装备偷渡中央。

**军令与设施。** 已成牌的奥秘／地标保留原军阵作者，后续布置也用卡片既定来源；新指挥者只是此刻下令的人，若公开记录需展示施令者，应另加activeActor快照，不能覆盖secretSource／landmarkSource。不能通过换帅刷新设施次数、冷却或重新隐去已揭示奥秘。

**其他效果。** 正在持续的临时攻击、冻结、沉默、护甲盾与部队伤亡归其原对象；换帅不解除。原技能造成的临时效果依原时点到期。未来若技能会在身份变化时追踪目标，须单独写因果规则，不能从本方案推定转移。

## 必须改动的范围与版本

若获授权实施，建议单独规则7及独立定义／AI版本，不能把替换塞进现有规则6。需要实际修改：新局配置和双侧候选合法报价、人物卡分配排重、角色访问层、正式原子动作、技能行动次数、来源与身份校验、AI仅基于合法公开信息、主将卡面／检查／演出、公开记录及战果角色列表、出征／三来源守城和隔离教学。旧世界迁移、旧战斗续接双轨、保存恢复均不列交付约束。

UI保持已有沙场与5:7卡面、固定主将／技能命中区。换帅卡点击或拖到自己的主将区域；候选与原亲卫来源详情可读。演出只更新原区域内容，不移动主将按钮，不遮挡护卫或改变攻击目标。快速、减少动态效果与取消都必须采用相同一个正式动作。新牌声音随用户音效暂缓要求继续暂缓，不作为实施阻塞。
