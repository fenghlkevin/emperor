# 产业用工与军役抽调

2026-10-19。保留原有开局人口、四业职业人数和75%劳动力比例。税率、口粮、薪俸、军需及装备计价仍沿用现行规则；只改变扩城用地、产业用工及征调来源。

## 扩城与产业

- 工部「城州扩建」每次5000两，正常人口容量增加10000人，可开发土地增加5000亩。最后一次土地增量可少于5000亩，但不能超过地形可开发土地上限；土地已满时拒绝扩建。只提高容量，不直接生成人口或提高产量。
- 四业继续共用土地。开发每亩2两、每笔1—500亩、施工、民夫占用、灾时暂停规则不变。
- 新资源规则首次启用时，把各业当时的面积与职业人数保存为用工密度基准，保持初始职业和产出不变。基准不随读档、征调和开发重新计算。
- 满员需求为 `ceil(生效面积 × 基准人数 / 基准面积)`；现有超额岗位保留，但无岗位不得继续增加用工。满员生产潜力随面积扩大，实际按 `min(1,实际人数/满员需求)` 生产，避免“新增面积×新增人数”重复放大收益。
- 开发完工后下一旬，从空闲劳力补入目标产业；缺员保留空岗，不凭空增人、不自动从其他产业抽人；已锁定岗位不自动招工，可在产业用工页手动补缺。土地转用在同一启用旬释放转出产业多余岗位，再给转入产业招工，总人口与土地守恒。
- 地方自动兴农和年度兴农采用同一用工规则。已委任地方不再暗中挪走其他行业人口。日后新增人口进入空闲池；现有「产业用工」页可在岗位范围内补缺或释放劳力。
- 普查及迁入事件的职业安排也受75%劳力与产业岗位限制，剩余人口保留在籍，不能绕过就业容量。

## 征兵和征民夫

兵部常规军务、军营舆图的征兵，以及工部新增「征调民夫」，共用一个计划器：先使用全部合格来源州的空闲劳力，再按玩家所选产业抽调。各业提供0、10%、20%、30%、40%、50%档位，含义是本次最多从该业现有人数抽调的比例；输入总人数仍须完整可满足，否则整笔拒绝，不静默少征。

每个来源州、每个行业累计仍在服役的抽调人数记为D、实际在业人数为W。追加抽调x会同时增加D、减少W，必须满足 `(D+x)/(W+D) ≤ 50%`，故最多追加 `floor((W-D)/2)`。四业合计另按同一公式限制，防止先调换职业再绕过总上限。士兵与民夫合计计入D；转营、跨州、跨旬和读档不清空来源记录。初始军民夫不虚构抽调历史。

军令和工部确认预览展示：一次性费用、四业人数与产量前后变化、民间总产粮、国库银税、军饷、民夫薪俸、军需、官府口粮、粮赋及常规钱粮净额。产值与国库银税分开；一次性征兵费4两/人只扣一次，不重复列为旬支。民夫没有新增一次性征调价，沿用现有薪俸和供粮开支。

遣散士兵及民夫会释放对应抽调记录。仍属同国且家乡容量足够的抽调人员返乡；原产业有空岗且劳力允许时优先返岗，否则进入空闲池。家乡已失去或无安置空间者留在当前州，不删除人口。民夫在建工程占用部分不能遣散。阵亡减少真实兵员、总人口和对应抽调记录，不恢复职业人口。调兵时抽调记录随部队转营，原籍不变；投降中央部队归入地方营时同步转移记录。

地方及外国自动征兵仍只使用空闲劳力，不未经玩家选择抽走产业人口。

## 存档与验收

`industryLaborVersion:1`、各州 `industryLabor` 保存固定用工基准和启用旬招工任务；`manpowerVersion:1`、`manpower.drafts` 保存原籍、驻地、职业、兵/役角色和人数。旧档补齐新字段，不重置现有钱粮人口；局部字段缺失、非法版本与来源人数超过实际在役人数拒绝载入。预览在副本上计算，保存失败不发布钱粮、人口、额度或序号变化。

验证：`tests/industry-manpower.test.mjs`；桌面 `npm run test:industry-manpower`，覆盖两处征兵、工部征调、钱粮预览、扩城用地、开发招工、失败重试、重载及900×680布局。

地形限制与特色产出采用[地形经济规则](terrain-economy.md)：沿用现有四类地形，四业分别受已解锁土地的固定比例上限约束，扩城受地形最终上限约束；旧档既有面积与在建项目保留。
