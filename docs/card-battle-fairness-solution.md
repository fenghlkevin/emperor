# 已撤回的同步指令方案

> 历史记录提示：本文件保留当时的设计与检查结论；本次实现以[生产版设计](card-battle-release-design.md)、[平衡复核](card-battle-release-balance.md)与[原型对照](card-battle-ui-comparison.html)为准。

日期：2026年10月22日  
状态：用户已明确否决，不采用，不作为后续开发方向。以下保留当时推演与数据供追溯；当前目标以[炉石式规则修订](card-battle-hearthstone-rules.md)为准。

## 1. 建议

保留现有卡牌画面、军令、攻击、生命、兵种和实际军队来源，将“某一方连续完成整个回合”改为“双方各下一条指令，同时结算”。每轮双方同步恢复军令和抽牌，没有先手席位、后手调兵令或额外手牌。

它与炉石的主要差别是行动时序。玩家仍然选牌部署、选己方部队再点目标，每次只决定一个动作。解决先后手问题的依据是双方使用同一份场面、互不可见的指令和对称结算规则，不能再用某个总体平均接近50%作为公平证明。

这是对原设计第2、3、16、17、19、20节有关回合、胜负时机、界面和验收要求的替代候选；军队预算、人物、训练和战后经济规则继续沿用。未采纳或实现前，原文仍作为失败基线保留，不能混合两套时序。

## 2. 为什么不继续只补后手

[前轮复核](card-battle-fairness-review-2026-10-22.md)已经发现：整回合制下，低费突袭军阵和纯高费军阵需要的补偿方向不同。调兵令跨过费用档位会让高费兵提前上场，多抽一张牌又不能消除某些低费军阵的攻击时序优势。

本轮还验证了一个更小的改动：“你做一个动作，我做一个动作”，每轮同时恢复资源，并由上次最后行动者的对方开启下一轮。覆盖72个镜像条件，每条件500个种子对、交换先后手，共72000局。

| 交替行动结果 | 实测 |
|---|---:|
| 72组等权先手得分 | 50.59% |
| 点估计位于47%～53%的分组 | 60／72 |
| 高训练纯重骑／武勇主将先手得分 | 68.30% |
| 同组95%成对近似区间 | 66.15%～70.45% |
| 中训练远程／武勇主将先手得分 | 60.00% |

交替行动改善了多数军阵，却仍有明确反例，所以本轮不推荐它直接定稿。这里的得分仍是“胜＋平局半分”，不是纯获胜率；数据来自同一简化策略模型，不是正式游戏或玩家实测。

## 3. 玩家实际怎么操作

开局双方均有4张真实手牌，含已有部队转换的2费前锋；初始均3军令。没有额外生成的免费士兵。

每一步的流程：

1. 双方基于当前公开场面，各自选择一条指令：部署一张牌、让一张部队攻击一次、使用一次主将技，或待机。
2. 指令在锁定前互不可见。单机AI先基于该步开始的场面锁定指令，再接收玩家提交；不得读取玩家本步所选牌、目标或鼠标悬停来改令。
3. 双方都已锁定后，同时展示并完成该步效果，再处理退场与胜负。
4. 只要还有一方行动，就进入同一轮的下一步。军令不会因进入下一步恢复。
5. 同一步双方都待机，才结束这一轮。随后双方军令上限一起加1、恢复军令、各抽1张，再开始下一轮；最高10军令，第一轮不额外抽牌。

待机只放弃当前这一步，不等于整轮退出。若你待机而敌军部署，下一步你仍可根据新场面下令。这样不需要加入“结束回合后还能不能回应”的特殊权限。

普通部队每轮最多主动攻击一次，部署后的下一轮才能攻击。突袭部队可在同轮后续步骤攻击敌方部队，仍不能在部署同轮攻击主将。部署与攻击分别占一条指令，不能出一张牌同时免费连续攻击。

抽牌、回血、登场伤害是其所属指令的一部分，不额外占一步。攻击不花军令；出牌照常扣对应费用；主将技2军令，每轮一次。

## 4. 同时结算的明确规则

### 4.1 目标看锁定前的场面

双方从同一份步初场面选择合法目标。已有护卫仍限制目标；本步刚部署的护卫，从下一步才开始阻挡攻击。不能用刚揭晓的部署反向改写对方已经锁定的合法攻击。

本步刚部署的部队不属于步初可攻击集合，也不吃本步按步初集合计算的全体伤害。新兵从下一步开始可被选为目标。这是公开的部署规则，不能只给玩家或外国其中一方。

### 4.2 已锁定的动作都会完成

若一张部队已锁定攻击，即使同时被敌军攻击、箭雨或主将技击败，它仍完成本次攻击和应有反击。全部伤害合并后统一退场，不能按程序遍历顺序先删掉某方动作。

攻击部队仍同时受到反击；被动反击不消耗该牌的主动攻击次数。若双方本步正好相互攻击同一对部队，只发生一次交锋，双方都消耗主动攻击次数，不能重复扣两次血。

例：甲为5攻10命，乙为3攻10命，双方互相下令攻击，结算后甲剩7命，乙剩5命。若仅甲攻击、乙待机，乙依然反击，结果也为7命与5命。

反骑、破盾的攻击加成只由本次主动攻击触发。双方互攻时双方都按主动攻击计算加成；“减反击伤害”不减免敌方同一步主动下令造成的攻击伤害。例外需要在详情和交锋预览中说明。

### 4.3 主将伤害和治疗

同一步治疗先按步初缺失生命计算有效回复，再合并本步伤害。满血时的治疗不能储存成额外生命来抵消伤害。双方使用相同公式。

全部效果完成后，若仅一方主将归零，该方败退；双方归零则双方收兵。相互攻击主将时不能因谁的动画先播放就先判胜。统一疲劳仍在双方都待机的轮末同时结算。

## 5. 原有军队体系如何保留

| 现有系统 | 本候选的处理 |
|---|---|
| 总兵力与亲卫 | 沿用实际来源、全军K牌额及亲卫生命覆盖，不按动作凭空发兵 |
| 预备兵 | 每个新轮最多补一张、消耗真实预备兵并替代常规抽牌；不是每条指令补兵 |
| 训练 | 只用现有训练度及原分档，不增加士气 |
| 普通统领与武将 | 沿用真实人物、属性加成上限和唯一武将规则 |
| 外国人物 | 先持久化真实人物，再按相同条件造牌，不临场随机补强 |
| 军粮 | 沿用出征整备与按旬军饷；指令步、轮次都不额外推进旬 |
| 战损与装备 | 每步按实际累计伤害记录，战后按来源统一结算一次 |

“条件相同”要同时包含兵力、兵种、训练、人物、装备、城防和AI策略。只让兵力与平均训练相同，不能要求骑兵打反骑兵、名将打普通统领都正好五五开。公平目标是同规则下差异可解释，国家身份不产生隐藏加成。

## 6. 独立推演结果与边界

在原独立设计模型上更换行动时序，未修改正式游戏引擎。主矩阵仍为8种军阵×训练20／60／90×三类主将，共72个镜像条件，每条件1000局独立牌序，合计72000局。另以新种子和偏进攻策略复核5个条件，共5000局。

模型沿用原报告中的简化：每兵种一名75主属性实际统领、主将生命32、无城防、无80属性普通带队加成。保留费用、训练、兵种能力、武将、预备兵、七个部队位和轮末疲劳。未覆盖生产游戏多来源组装、外国人物生成、经济结算或真实玩家策略。

| 规则检查 | 结果与范围 |
|---|---|
| 双方身份、牌序归属交换 | 300组逐步比较通过；每步状态及最终胜负按身份对应交换 |
| 正向／反向遍历结算 | 同300组逐步比较通过；不能因程序先处理玩家而占便宜 |
| 改写旧“先手”字段 | 同300组不改变场面与结果；新规则不依赖该字段 |
| 完全同牌序、同决策 | 300局都保持对称并收兵；没有任一席位凭结算顺序获胜 |
| 军令、手牌、场位及模型兵员守恒 | 137624次侧状态检查通过，仅覆盖标准100人模型 |
| 正常起手可部署 | 上述300组的600侧初始状态通过 |
| 明确边界例 | 7项通过：互攻只结算一次、同时击败主将、死亡仍完成攻击、新护卫延后生效、双方待机换轮、全体伤害排除本步新兵、突袭不打主将 |

这些检查支持候选具有预期的对称性，但有限样本不是对正式实现所有状态的数学证明。模型中没有先手席位，因此不再统计“先手胜率”。A／B得分只描述独立牌序样本，不能把两者混淆。

主矩阵A席总体得分为49.93%，分组点估计范围46.85%～55.15%；每行置信区间保存在结果JSON中。多数单组1000局的区间仍宽于47%～53%，不能宣布每个分组都已通过该窄幅统计门槛。整体均值只作描述，主要结构证据是固定输入交换身份与遍历顺序的逐步重放。

### 仍未解决的可玩性问题

- 纯刀盾、低兵力等防守对局仍偏慢，部分条件中位数达到24轮，未达到原定8～12轮目标。
- 纯刀盾训练20／武勇主将有60.2%收兵；高训练纯重骑／智谋主将有57.4%收兵。后者有同时击败主将的情况。不能把大量收兵带来的接近50%当作好玩的证明。
- 当前决策器不预测双方本步指令组合，只是公开场面启发式。需要验证更合理的防守、集火与治疗决策，并对称调整护卫、攻命与终局节奏。
- 本轮不证明所有兵种互战、训练收益、兵力收益都已达到原设计目标。这些交叉强度试验仍需单独完成。

因此结论是“有消除固定先后手席位的结构方案”，不是“77000局证明整款游戏完全平衡”。数值和体验不冻结。

## 7. UI沿用与必要变化

保留当前战场背景、卡框、主将区、费用／攻击／生命位置与选中高亮。玩家主要操作仍为选牌部署，或选己方部队再选敌军目标，提交后系统同时展示双方指令并播放结果，不要求玩家再操作敌方回合。

原“结束回合”按钮改为“待机”，旁边简短显示“双方待机后进入下一轮”。顶部显示“第N轮·第M步”，军令仍明确显示当前值与上限。普通新兵标记“下轮可攻击”，突袭标记“可攻击部队”。

交锋预览展示该次攻击与反击贡献，不把未揭晓的敌方另一条指令假装算成已知最终结果。同一步刚部署的牌暂有简短“部署中”状态，结算完成后可被下一步攻击。

存档需记录步初场面版本、双方已锁定指令、轮／步编号、军令与攻击次数、各独立随机流和结算提交状态。重开不能重选AI指令，动画重播不能重复扣兵扣装备。旧战斗仍按原规则版本续战。

## 8. 后续验收顺序

1. 先对称调整防守拖局及同时败退比例，加入预测对手可能指令、但不窥视实际指令的同一AI策略。
2. 用独立新种子复核，分别报告身份对称性、收兵、时长和全部分组；再做兵种、训练、兵力与武将交叉强度试验。
3. 规则确认后才接入正式战斗引擎，重做身份交换、执行顺序、保存恢复与兵员装备守恒检查。
4. 使用保留的UI完成实际出牌、攻击、待机和结算验收；满足门槛后再替换试玩入口。

本轮只交付候选设计、独立模型和结果，当前游戏仍使用原试玩时序。全部设计资料位于`codex/card-battle`工作树，不在`develop`开发。
