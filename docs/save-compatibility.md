# 存档版本兼容

当前约定以 `game.mjs::validateSave`、`domestic.mjs::migrateDomestic` 和各模块校验器为准。本文件区分外层版本、同版本缺失字段补全和历史归档记录；不支持的档案不能靠手改版本号修复。

## 支持矩阵

| 数据层 | 当前格式 | 兼容范围 |
| --- | --- | --- |
| 游戏封装 | `version: 2` | 仅接受 2；version 1、缺失版本或未来版本拒绝 |
| 内政 | `domestic.schemaVersion: 8` | 仅接受 8；schema 1–7、缺失或未来版本拒绝，不转换军制；同版本势力扩展见下一项 |
| 世界势力 | `worldExpansionVersion: 1` | 完整的旧34国、43州 schema 8 档案补入8个外围势力，旧钱粮、军备、外交与占领记录保留；新标记已存在时不补造缺失国家 |
| 兵种装备 | `troopKits.version: 1` | 必须存在完整九兵种驻地库存及占用；旧散件库存、缺失军备拒绝，不补发免费装备 |
| 玩法平衡 | `balanceRulesVersion: 1` | 缺失补1；保留既有寿元、年龄、钱粮、装备与终评，不补偿旧消耗；未知版本拒绝 |
| 皇帝量纲 | `emperorRulesVersion: 1` | 缺标记时按旧量纲验证并转换一次；显式未知版本拒绝 |
| 全国钱粮 | `nationalResourcesVersion: 1` | 同 schema 8 的旧州库存合并至所属国家一次；保留历史单据，拒绝混合新旧库存 |
| 财政记账 | `fiscal.accounting.version: 1` | 可对同内政版本下缺少 accounting 的记录建立基线，原流水标记 legacy，不据旧账改写余额 |
| 当前战场 | `battle.version: 2 / command.kitVersion: 1` | 使用当前套装战斗；守城另有 deploymentVersion 2；不承诺迁移旧战场格式 |
| 当前生成终评 | `reignResult.version: 2` | 生成历史依据和累计战绩；已归档 version 1 终评保留并按旧语义校验 |
| 业务模块 | 多数独立 `version: 1` | 仅执行对应 initializer 明确实现的补值；缺失不是普遍可修复，损坏的部分结构仍会拒绝 |

`SAVE_KEY = emperor.save.v1` 与 `SLOTS_KEY = emperor.save.slots.v1` 是保留的存储键名，不代表载荷版本为 1。自动档位 slot:0，手动档位 slot:1–slot:10。JSON 导入上限 8 MiB；浏览器预览与 Electron 的本地存储各自独立。

## 同版本补全的具体含义

以下补全只发生在外层 version 2、内政 schema 8、军备有效且通过完整校验的前提下：

- 缺 `saveRevision` 时从 0 开始。载入档位或创建王朝后，以当前内存提交序号为基线；成功提交递增，不以磁盘档位中的旧序号作为跨窗口锁。
- 缺 `phase` 时从早朝阶段 0 开始。缺皇帝规则标记时，已有四能力须在旧 0–100 范围内，乘 5；旧体力上限乘 20 且最高 500，当前体力按比例换算。已带规则标记不重复换算。
- 缺 `nationalResourcesVersion` 时，先核对旧地方库存与粮账，按所属国家汇总粮食、将地方现金合入国库（负余额不足部分转债），删除地方库存与地方粮账。已有完整财政账时记录当旬合并交易；新局/无历史账的余额作为期初。已有标记的档案缺全国粮库或仍有地方库存均拒绝，重复载入不再次合并。历史购粮、调粮与补助单据保留原义；旧购粮额度随迁移废止，全国新购粮额度按首次购买锁定。
- 缺财政 accounting 时，以真实国库、债务为基线保留旧账；不会根据预算倒推现金。同旬首次新交易把旧账放入 legacyBaseline。
- 产业、粮食救济、国家发展等可在整体记录缺失且没有互相矛盾的新格式活动记录时补空队列或基线。全局已存在却缺州记录、已有活跃项目却缺全局册等情况由各模块拒绝。
- 缺官员能力、性格、关押记录等时按模块规则补齐；人物评级、性格与开放名单也可能按模板版本同步。这不是纯结构检查，不能承诺所有历史元数据原样不动。
- 缺出行、炼丹、祥瑞、宗室、结局与功业模块时按已有规则初始化；旧在途出行不补造巡游事件，旧档炼丹不补发新局药材。
- 旧战绩只从仍保留的战报建立累计基线，标记 retained-history；被裁剪的历史不推测胜负或伤亡。旧版终评不会升级成伪完整的新版评价。
- 使臣形象按 `envoy-portraits.mjs` 将其支持的历史形象记录归一化为 version 3；不会因此接纳不受支持的外层存档或军备格式。

`validateSave` 会先调用部分初始化器，再进行各模块校验，并同步 stats 国库/威望；寿元为零且尚无终评时会生成终评。调用方如需保护原对象，应先 structuredClone。归一化后的数据结构见[数据字典](data-dictionary.md)和[类型声明](../src/game-types.d.ts)。

## 失败与恢复

无法识别的版本、缺失军备、无效数值、重复 ID、归属矛盾、流水不平衡和非法出战占用都会拒绝读取或提交。继续游戏读取失败只显示无法读取，不自动清档；玩家可以导入支持的备份或另开王朝。保存失败时不发布候选内存状态；双存储键写入失败会尽力恢复档位列表，仍应保留可导出的备份。

历史说明中“version 1 自动升 2”“schema 1–6 顺序迁移”描述的是旧实现，当前已停止支持。未来如恢复兼容，必须提供明确转换逻辑、资源守恒与重复载入测试，再调整本矩阵。

平衡规则1不变更外层2、内政8或套装1。旧档接续后采用新价格、休息、商业、公共服务和储粮规则；既有其他收入保留，新局本国中央其他收入为400两/旬。历史供粮快照缺`storageLoss`按0校验，不补算历史损耗。

### 城州容量（2026-10-19）

同schema旧档在完全没有容量记录时补建 `capacityRulesVersion:1` 和各州 `cityCapacity`，保留原有实际资源及在建土地。已有容量记录不可通过删除某州字段重建上限，非法值与超额占用拒绝载入。详见[城州容量](city-capacity.md)。

### 产业用工与征调来源

同schema补建固定用工基准、招工队列及抽调来源记录，不修改现有职业人口。来源记录随读档保留；容量标记存在但局部基准缺失、征调来源标记存在但账本缺失，或来源超过实际在役人数均拒绝加载，不能通过删除局部字段重置50%额度。规则见[产业用工与军役抽调](industry-manpower.md)。

## 地形经济（2026-10-19）

采用现有四类 `terrain`。新增 `domestic.terrainEconomyVersion:1`、各州 `terrainCapacity:{version:1,kind,landLimit,legacyLand,legacySectors}`。新局按地形设置土地共池和四业上限，保留初始化人口与75%劳动力比例。旧档既有用地、在建项目和人口均保留，迁移基线只登记一次；部分字段缺失或记录篡改不得重置上限。特色加成进入统一生产函数，不改税率及钱粮开支。详见[地形经济规则](terrain-economy.md)。

## 州县地理归类（2026-10-19）

新增 `domestic.geographyVersion:1`，43个现有州县与外国腹地集中配置。旧档先校验地形容量快照，再迁移 `terrain`；保留既有用地、在建项目、人口、职业、钱粮及实际流水，地形容量记录只更新未来上限及必要保留值。相同版本不重复迁移。详情见[州县地理归类](province-geography.md)。
