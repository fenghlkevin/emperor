## UI与动画

按最初原型重新还原场景、城墙军阵、火光、雕木桌面、铜饰主将框和青玉按钮。中场与手牌分别设计：场上是5:7竖向长方形满幅立绘、名称与攻命；手牌有费用珠并自然扇形排列；普通无技能部队满幅立绘、底角攻命，有技能部队和人物保留说明纸面，攻命位于插画与说明的交界。卡框采用带旧纸纤维、铜饰刻纹和厚度阴影的实物材质。场上卡框正置，持续动画只作用于立绘、光影与微粒。计策有12幅独立插画。部署动画从完整手牌渐变为战斗卡；抽牌、攻击、箭矢、受伤、治疗、护盾、退场与换回合提供相应反馈。

[原型对照](card-battle-ui-comparison.html)包含原图、整场实机、部队的两种卡面和百人牌册。七个部队位与本人主将是后续确认的功能要求。

## 运行与复查

运行 `npm run preview:card-battle -- --compare` 同时打开完整起手试玩与原型对照窗口；显式加 `--showcase` 可查看可操作中局。试玩使用隔离临时配置和独立自动保存。

[完整生产设计](card-battle-release-design.md) · [卡表](card-battle-release-catalog.json) · [平衡结果](card-battle-release-results.json) · [美术来源与提示词](card-battle-assets.md)

当前预设卡牌“主力／精锐”是费用档位，编牌剩余部队按两主力一精锐加入，不是训练评级。最新修订保持卡表、伤害计算、洗牌抽牌与战斗编牌规则不变；修复动画先后与时长、结束按钮效果，并将两处默认出征草案由100名子队兵改为库存允许时450名子队兵，避免默认牌组26张计策。旧战斗牌库保留。动画录屏使用明确的动效验收场景；其中10生命等测试属性不代表该卡的基础数值，基础费用／攻命以正式卡表为准。

[四种攻击实机录屏](screenshots/card-battle-v3-attacks.webm)：正常速度下蓄势300毫秒、冲刺500毫秒、命中停顿220毫秒、回位500毫秒，命中光效880毫秒，数字1100毫秒。先提交真实状态保障存档，界面生命、护甲与死亡在命中才更新；敌方动作使用相同时序。结束按钮有就绪玉光和点击扩散，系统减少动态效果时关闭。

默认550人草案含100亲卫和450子队兵，不额外扣钱、购买兵装或自动落印；人物随实际参战将领编牌。出征前和战斗内均显示牌组构成。随机抽牌仍可能连续出现计策；[抽牌审计](card-battle-draw-audit.json)没有发现抽牌只取计策的问题，100名子队兵产生26计策是原编牌规则导致的实际风险。

## 持续状态与退出调查补充（2026-10-22）

卡面新增持续状态短标签、强化／削弱属性颜色，详情列出当前生效与基础／持续／本回合属性拆分。命中提示明确攻击、生命上限等各自变化。三种窗口均验证结束回合文字留白；状态到期、沉默清除和护甲盾消耗不保留旧标记。新增3项纯显示模型测试、21项真实界面验收，技能18项、选卡13项和攻击34项回归通过。

退出核对：本轮旧试玩控制台明确记录SIGINT，来自为验收停止旧进程的操作。系统DiagnosticReports没有2026-10-22命名的Electron崩溃报告；真实应用runtime.log最后可见启动记录在10月21日。以上证据支持这次窗口消失与停止试玩进程有关，不足以证明所有前端异常都不存在。原诊断的console-message监听采用旧参数签名，现修正以实际捕获现代Electron的渲染错误。

试玩改为按工作树隔离的临时配置，不触碰真实存档键；每次合法行动先校验、写入隔离存档再更新内存。重新打开试玩、画面重载和一次自动渲染恢复都从最后提交状态继续，避免动画期间重复出牌／扣血。主进程接入既有渲染恢复机制，并记录进程停止、无响应／恢复响应、子进程退出与启动失败。[7项恢复验收](card-battle-recovery-validation.json)使用隔离测试配置，模拟renderer-loss事件，没有制造一次真实系统崩溃。

本轮最终 `npm test` 为849/849通过；持续状态21项、试玩恢复7项通过。此前被停止的旧试玩仅存于内存，无法还原当时进度；新增的隔离存档与恢复用于后续试玩。
