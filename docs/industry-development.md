# 四业开发与职业人口调配

实施日期：2026-10-16。范围：P0四业开发和同州职业调配，沿用[开发方案](research/emperor/P0内政与财政开发方案.md)的试行参数；建筑收益、粮食救济、地方委任策略保持原状。

## 操作入口

早朝召见工部尚书，在“普通营建、产业开发、职业调配”之间切换。户部的本国总表和经济报告可跳转到工部，选中某州时保留该州上下文。非早朝、状态不足或有未完成战争时，仍遵守原有办理限制。

开发前可查看四业已开发面积、容量、剩余面积、职业人数、当前条件下的预计下旬产量及开发后的州税收。职业调配同时填写四业目标人数，预览各业产量、税收和未分配人口。预览固定当前人口、生产率、税率，不包括未来灾害与事件。

查看、试算和取消不消耗资源；成功确认后统一保存，消耗一次现行政务行动。保存失败会保留原国库、人口、工程、体力、回合、命令序号和调配次数，可以重试。

## 开发规则

|项目|本项目试行规则|
|---|---|
|单价|2两/亩，开工时一次足额支付，由统一国库流水登记|
|单笔范围|1—500亩的整数，不超过所选行业剩余容量；不自动截断或多收费|
|工期|1个正常施工旬；开工当旬不推进|
|队列|每州最多一项产业开发，与普通建筑队列独立，可同时进行|
|劳力|费用包含雇工，不占用或转换四业、士兵及民伕人数|
|灾害|活跃灾害中禁止新开工；已有开发暂停，灾退后恢复，不再次收费|
|完工收益|完工时增加开发面积，新增产出从完工后的下一旬开始计入|
|失地|项目与已付费用留在当地，继续依当地灾情推进；玩家不能新操作失地，不重复退费或扣款|
|取消退款|首版不提供，提交前确认费用和收益|

例如第1旬开工，第2旬无灾正常施工完工，第2旬生产和税收仍用原面积，第3旬开始使用新增面积。若第2旬受灾，则延后到第一个正常施工旬完工，并在其下一旬增产。

开发只改变所选行业面积，不修改行业容量或基础生产率。四业仍采用既有公式：

`round(职业人数 × 行业系数 × 已开发面积/容量 × 基础生产率/100)`

当前规则：农业、牧业产粮（石），商业、工业产银（两）。资源新制在相同有效用地、用工、生产率下，农业0.18石/亩、牧业0.06石/亩，农业为主粮、牧业补充。农牧合并先保民间口粮，再征粮赋；仅工商构成银税税基，不对农牧重复折银。工业原件数按0.8折银后直接显示银两，征税时不再二次乘0.8。旧用工公式保留其基准：农业0.075、牧业0.012×2折粮、商业0.16、工业0.09×0.8折银；新制农牧采用上述有效用地公式。历史账目不重算。

## 职业调配规则

同州农业、牧业、商业、工业与未分配人口之间调配，每州每旬限一次成功调配。不另收银两，但同样消耗一次政务行动并保存一笔零金额操作记录。全部目标必须同时合法才提交；未改变人数的空操作拒绝，不消耗次数。

`未分配人口 = 总人口 − 四业人口 − 士兵 − 民伕`

这采用当前游戏的人口简化口径，没有新增劳动年龄结构。士兵、民伕不可作为调配输入；中央军仍是来源州士兵的子集，不另计总人口。四业目标合计不能超过扣除士兵、民伕后的可分配总量；非法输入、负数、小数、缺少行业和额外军事字段全部拒绝。

登记人数立即改变，报表和预估随之更新；实际生产在下一次旬结算发生。总人口与口粮需求不因调配而改变；粮食库存不会在点击调配时直接变化。普查、特赦、祥瑞、招募和调兵继续沿用现有规则，下一次调配和预估读取它们变更后的同一人口数据。

## 存档与结算

新增独立版本的 `industryActions`，保存命令序号和最近100条开发、调配、完工记录。各州 `development` 保存队列、最后施工旬、最后成功调配旬及完工启用标记，不改变普通建筑工程结构。

没有这些字段的旧档在实际存档旬建立空队列，不补发面积或产量、不修改人口银两、不重扣现有普通工程。迁移可重复执行；新格式局部缺字段、无效版本、非法面积、超容量项目、错误费用、错误启用时间或未来调配时间会被拒绝。

常规财政与粮食先按该旬有效面积结算，再推进产业开发；完工标记还会限制显式指定完工旬的生产计算，避免提前调用开发推进函数而使同旬产出提前增加。报表中的产量是按当前条件预估的下旬产量，与实际上一旬产出区分。

实现由 `economy.mjs` 共享既有公式，`industry.mjs` 处理命令、校验和队列，工部界面复用 `persistCandidate` 提交。新增开发费用和零金额调配均经 `postTreasury`，与[统一财政流水](finance-accounting.md)保持同一余额和命令防重机制。

## 验证

`tests/industry.test.mjs` 覆盖方案D01—D07及额外边界：四业公式、完工延后生效、税粮一致、尾数收费、灾害暂停、独立队列、人口守恒、调配次数、失地、旧档、坏档、保存失败和体力耗尽回滚。

`npm run test:industry` 使用独立临时档案运行Electron表单验收，覆盖预估、查看取消、开发与调配、重复点击、失败重试、额度重载、户部跳转的可见性与点击、灾退完工、旧档和900×680窗口。现有内联样式CSP提示单独计数，不在本次扩展中修改样式策略；其他控制台错误会使测试失败。

本轮结果：195项单元测试全部通过（含15项产业专项）；产业桌面验收与财政桌面回归均通过。已检查900×680窗口截图，确认按钮在可视区域，长表单可滚动。

## 攻略数值状态

2两/亩、500亩、1正常施工旬、每州每旬一次职业调配均为方案试行值，不是已验证原版数值。保留当前产出模型，没有套用攻略候选的“开发面积/职业人口、民忠限制效率”公式，也未判定按人数最多或按最弱行业开发为唯一最优策略。后续调平可以调整参数，守恒、费用一次入账、完工时点和存档兼容仍需保持。

## 2026-10-19 土地与人口约束更新

当前规则以[城州共用土地与人口承载](city-capacity.md)为准：四业共用州级可开发土地，原各业 `capacityArea` 仅保留为产出计算基准；工部支持土地转用及人口容量扩建。上文独立行业容量与旧职业口径属于先前阶段记录。

## 2026-10-19 产业用工与军役抽调

扩城同时增加人口容量和可开发土地；产业开发在启用旬从空闲劳力安排对应人口，缺员按比例生产。工部可征调/遣散民夫，兵部两入口可选择产业抽调，士兵民夫共享累计50%上限，确认前显示减产与新增开支。详见[产业用工与军役抽调](industry-manpower.md)。

## 地形经济（2026-10-19）

采用现有四类 `terrain`。新增 `domestic.terrainEconomyVersion:1`、各州 `terrainCapacity:{version:1,kind,landLimit,legacyLand,legacySectors}`。新局按地形设置土地共池和四业上限，保留初始化人口与75%劳动力比例。旧档既有用地、在建项目和人口均保留，迁移基线只登记一次；部分字段缺失或记录篡改不得重置上限。特色加成进入统一生产函数，不改税率及钱粮开支。详见[地形经济规则](terrain-economy.md)。

### 刺史办事经验

本州产业开发或转用、普通建设、特殊工程实际竣工时，给完工当时本州在职刺史增加1点经验。开工、暂停、停建和特殊工程分段完成不发放；重复结算不重复发放。刺史空缺、离职、收押或州已失去时不发放，经验上限100，保留原有年度在职经验增长。

当前救灾经验接在购粮救济：全国有预计粮食缺口且购粮成功时，给办理目标州的在职刺史增加1点；全国每旬只在首笔购粮时判定，拆单或切换目标州不重复发放。正常储粮采购不增加经验。
