# 皇帝原版时间与行动规则

整理日期：2026-10-16。本篇说明 DOS 原版的行动、日期、结算与事件如何衔接，供玩法讨论使用。本轮只复核已有证据与整理文档，未重新运行 DOS，也未修改游戏代码。

## 证据标记

|标记|含义|
|---|---|
|【攻略】|用户提供的玩家攻略；不等于程序规则|
|【原版静态】|已定位原程序指令、字段或字符串；未据此宣称所有实际流程通过|
|【原版实测】|已有 DOSBox-X 内原始 EMPEROR 函数的受控执行记录；不等于完整鼠标游玩|
|【指令模拟】|有限解释器执行原始指令，外部调用可能记录或替代；不能当 DOS 实测|
|【待证】|证据不足，保留问题，不补造规则|

主要依据：[原版时间规格](../../../reverse/emperor/replica-design/04-turns-and-characters.md)、[时间调度报告](../../../reverse/emperor/rules-analysis/turns/README.md)、[DOS 运行记录](../../../reverse/emperor/validation-round3/runtime/README.md)。较早报告与后续订正冲突时，按具体指令与对应验证范围判断。

## 时间有四层

|层级|原版含义|推进条件|证据|
|---|---|---|---|
|行动进度|一个半月阶段内累计的行动量，通常为0、1、2|按场景耗时增加；达到3则归0并推进一次半月|原版静态，普通边界已有实测|
|半月阶段|上旬、下旬|上旬结束进入下旬；下旬结束进入下月上旬|原版静态及实测|
|月份|1至12月，程序存0至11|结束下旬后递增|原版静态及实测|
|年序号|在位时间相关的年份计数|12月结束后递增，月份归至1月|原版静态及实测|

【原版静态】原版没有中旬，一年共24个半月阶段。若始终采用耗时1的普通行动，一阶段对应3个行动单位；这不意味着每年固定只能点击72次。零耗时场景、直接结束阶段和强制到月界均会改变操作次数。

【待证】场景编号与全部中文地点、菜单操作尚未一一对应。因此不能把“进一间屋”“点一次官员”或“退朝”统一定义为原版的一次行动。

当前项目 README 中的每月三旬、每旬六时段属于现有实现。本篇不将该规则混入原版时间模型。

## 行动如何推进日期

【原版静态】行动提交先处理场景耗时，再判断行动进度。基础耗时表中既有0也有1；场景13、14直接将进度设为3。特殊模式值等于1时，场景12还会额外加3，但该模式对应的精确菜单名称尚待确认。

达到3后，程序只推进一次半月，剩余进度丢弃。例如原进度2再增加3，最终是下一半月进度0，不是下一半月进度2。【指令模拟】已有超额进度用例支持这一点。

|起点|普通耗时1行动后的结果|证据|
|---|---|---|
|3月上旬，进度0|3月上旬，进度1；不触发半月推进|原版实测|
|3月上旬，进度2|3月下旬，进度0；受控地区训练减1|原版实测|
|3月下旬，进度2|4月上旬，进度0；执行月更新及费用扣除|原版实测|
|12月下旬，进度2|次年1月上旬，进度0；皇帝年龄20变21|原版实测|

这些是原函数受控输入的结果，不能据此推断所有宫殿行动具有相同耗时。原始记录见 [calendar-live.json](../../../reverse/emperor/validation-round3/runtime/calendar-live.json)，跨月与费用摘要见 DOS 运行记录。

## 不同周期各自处理什么

|时点|已确认的主要业务|证据与边界|
|---|---|---|
|每次进入普通行动结算|检查半年分类账归零条件、清待处理事件槽、累加场景耗时|原版静态；并非每次都推进日期|
|每次跨半月|更新独立计时矩阵；地区状态损失、训练、增援、分摊入账；工程推进|原版静态；训练衰减有受控实测，非全部分支实测|
|每次跨月|相关任务倒计时；怀孕计数增加；符合模式的地区自动开发；扣月费用；清到期调用标记|原版静态；月费用有实测|
|每次跨年|皇帝、后宫、官员、子女增龄；符合条件的外邦贸易年数增加|原版静态；皇帝增龄有实测|
|进入1月或7月|玩家地区半年生产、税收、财富等级与人口计算等|原版静态；部分指令模拟，完整半年收支尚未全部归因|
|事件扫描与消息消费|按游标和行动进度检查、展示并消费事件|原版静态；不能视为固定每月触发一次|

【原版静态】普通跨年顺序为：

```text
旧年12月下旬结束
  → 半月计时与地区工程推进
  → 月更新，先扣月费用
  → 月份回到1月，年份递增，人物增龄
  → 半年生产与税收等结算
```

工资先于半年税收入账。是否出现暂时负资金，以及后续是否补征，必须按这些时点判断。仅从1月上旬推进至1月下旬不会再做半年结算。

【原版静态】半年分类账另有缺陷：在1月、7月上旬，每次普通行动开始都会清十项分类统计，不要求行动进度为0。这不清国库资金。报表统计被清与实际资金损失是两件事。

## 强制到月界与休息要分开

【原版静态＋指令模拟】存在强制推进到下月的独立入口：当前上旬时处理两次半月业务，下旬时处理一次，随后按月、年、半年顺序更新，行动进度归0。已定位到部分场景成功路径，但中文操作映射未完整恢复。

【待证】不能将这个入口概括成“所有休息必过一个月”，也不能用于解释所有读档。攻略称部分紫宸殿活动“下一回合生效”，尚需对应具体排队标记和调度入口。

## 行动成本有三个独立维度

|维度|控制什么|已确认的例子|
|---|---|---|
|行动耗时|何时跨半月、跨月|场景耗时与进度阈值|
|体力与健康|皇帝能否继续行动、是否进入恢复状态|休息恢复、体力不足进入过劳态|
|寿命|皇帝剩余生命资源|部分休息、连续临幸和恢复态会扣寿命|

【原版静态】消耗体力不自动证明消耗一个行动单位，恢复体力也不自动证明进入下个月。年龄按年增长，剩余寿命则由行动和事件另行改变。显示估计使用“年龄＋剩余寿命除以48并截断”，不能反推每年必扣48寿命。

### 独寝恢复

【原版静态】已定位的休息分支先加健康5，再按身体状态处理：

|休息前状态|体力|寿命与状态|
|---|---|---|
|正常|增加150，最高不超过体力上限|行动进度恰为2时额外扣寿命2|
|过劳|补满|扣寿命30，转入后续恢复状态|
|健康不足|补满，另加健康80|扣寿命30，转入后续恢复状态|

通用辅助将健康、快乐最高限制为100，最大体力最高限制为500；增加体力上限不会同步补足当前体力。体力降至0会进入过劳恢复态，不能直接称为死亡。

【原版静态】特殊模式值等于1时，单次寿命扣减小于10会先乘12；扣减10及以上不按这条放大。故上述寿命数字仍需经过通用扣减规则。

【攻略】金龙殿“体力加150、健康加5”与正常分支吻合，但省略了进度、身体状态与寿命条件。四处修习各扣体力20、炼丹入殿扣10等仍按攻略记录，尚无完整地点成本表可确认。

### 后宫恢复与连续行为

【原版静态】连续选择临幸会累加连续次数。寿命费用随次数变化，正常首次选择的费用为2，之后依次为4、8、16、24、32，达到7次及以上为35；行动进度为2时另扣3。快乐增加5，扣寿命仍经过上述特殊模式规则。

已有后宫人物的恢复能力为：

```text
恢复能力 = 截断(外貌² / 40) + 当前经验 + 名分加成
按该能力恢复体力并封顶，然后相关流程增加人物经验
```

名分槽0至4加50，5至13加20，14至33加5；新遇人物另有只使用外貌平方项的分支。精确写入顺序见原版时间规格。

【攻略】“外貌×3−88＋职务附加＋经验”与已定位恢复能力公式不同。需要区分能力字段用途和游戏版本，现阶段应采用有指令证据的公式描述该恢复分支，不能把两式混用。

【待证】取消、暂离、恢复场景是否重复收费，以及连续次数在所有中断路径中何时清零，尚未完整覆盖。

## 事件不是一次性全量结算

【原版静态】业务事件按1至60的游标分批扫描；事件表要求的行动进度必须与当前进度相符才检查。内乱、暴动、饥荒及多种灾害要求进度0，地震要求进度2。命中一个事件后停止当前扫描，等待展示和消费，再继续后续事件。

因此，“当前没看到灾情消息”不等于地区状态没有变化；“跨年”也不等于所有人物死亡事件立即各检查一次。内乱、暴动、饥荒解除后先进入“结束待报告”状态，消息消费才清回无事件状态。

## 读档会执行额外业务

【原版静态】读档包含两层：先读取存档，再由主循环恢复。后者会额外调用一次地区与工程推进，然后恢复保存的场景；场景构造还可能产生自己的副作用。

|说法|结论|
|---|---|
|【攻略】每读档一次必过一个月|不成立为通则；已定位恢复路径不直接增加年、月和半月|
|读档完全不改变业务状态|也不成立；工程、训练、灾害等可能再推进一次|
|只要日期没变，读档就没有代价|不成立；状态副作用与日期递增是不同路径|
|所有读档后变化均由时间推进造成|不能这样归因；还要观察场景恢复、事件消费等|

【待证】已有静态契约尚缺读档完整端到端覆盖。必须分开比较“刚解码”“恢复业务后”“场景构造后”，不能只看最终存档就断言原因。
